= Supported network types for third-party CNI plugins

[role="_abstract"]
When you install on-premises {ocp-short} clusters by using the {cim} feature, you can select a third-party Container Network Interface (CNI) plugin instead of the built-in OVN-Kubernetes option.

To use a third-party CNI, set `spec.networking.networkType` on the `AgentClusterInstall` resource and provide CNI manifests by using the `spec.manifestsConfigMapRefs` field. See _Configuring third-party CNI plugins for on-premises cluster installation_ in the additional resources section for more information.

All third-party CNI options (`CiscoACI`, `Cilium`, `Calico`, and `None`) require you to upload CNI manifests before installation.

The following table shows supported values for the `spec.networking.networkType` field in the `AgentClusterInstall` resource, and for `spec.networkType` in the `ClusterInstance` resource:

.Table of supported network types 
|===
| Value | Description | Custom manifests required

| `OVNKubernetes`
| Default CNI for {ocp-short} (recommended)
| No

| `CiscoACI`
| Cisco ACI CNI
| Yes

| `Cilium`
| Isovalent Cilium CNI
| Yes

| `Calico`
| Tigera Calico CNI
| Yes

| `None`
| No CNI. You provide all networking manifests.
| Yes
|===
