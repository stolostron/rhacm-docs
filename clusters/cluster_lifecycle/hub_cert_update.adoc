= Updating the hub cluster _KubeAPIServer_ certificate

[role="_abstract"]
If your managed clusters already trust the full certificate authority (CA) chain for the new hub certificate, you can update the certificate directly when you move to a new root CA. Update the certificate directly when you renew the certificate with the same roots, or if your strategy already includes the trusted roots.

*Required access:* Cluster administrator

.Prerequisites

* Your managed clusters trust the full certificate authority (CA) chain for the new hub certificate.

.Procedure

. Follow the steps in link:https://docs.redhat.com/documentation/en-us/openshift_container_platform/4.19/html/security_and_compliance/configuring-certificates#api-server-certificates[Configuring API server certificates] in the {ocp-short} documentation to update the `KubeAPIServer` certificate. Ensure the certificate file includes the complete chain in the correct order. See the following list of the chain components:
+
* Leaf certificate
* Intermediate CA certificates
* Root CA certificate

. Verify that managed clusters are available at least 15 minutes. Run the following command. Make sure the status in the output is `AVAILABLE=True`:

+
[source,bash]
----
oc get managedclusters -w
----
