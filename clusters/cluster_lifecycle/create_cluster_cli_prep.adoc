= Prepare to create a cluster with the CLI

[role="_abstract"]
Before you create a cluster with the CLI, complete the following preparation steps.

.Procedure

. Make sure the ClusterImageSet resources are available on the hub cluster by running the following command:

+
[source,bash]
----
oc get clusterimageset -A
----

+
The output might resemble the following example:

+
[source,bash]
----
img4.18.4-multi-appsub     quay.io/openshift-release-dev/ocp-release:4.18.4-multi
img4.18.4-x86-64-appsub    quay.io/openshift-release-dev/ocp-release:4.18.4-x86_64
----

+
*Note:* Each ClusterImageSet references an {ocp-short} release image. The ClusterImageSet resources are populated by the `cluster-image-set-controller` in {mce}.

. If you use the Nutanix platform, use the `x86_64` architecture for the `releaseImage` in the `ClusterImageSet` resource and set the `visible` label value to `'true'`. See the following example:
+
[source,yaml]
----
apiVersion: hive.openshift.io/v1
kind: ClusterImageSet
metadata:
  labels:
    channel: stable
    visible: 'true'
  name: img4.x.47-x86-64-appsub
spec:
  releaseImage: quay.io/openshift-release-dev/ocp-release:4.x.47-x86_64
----

. Review the hub cluster `KubeAPIServer` certificate verification strategy and update the strategy if needed. To learn what strategy to use for your setup, see xref:../cluster_lifecycle/set_verification_strat.adoc#set-hub-kube-api-server[Configuring the hub cluster `KubeAPIServer` verification strategy].
