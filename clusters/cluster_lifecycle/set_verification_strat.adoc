= Hub cluster `KubeAPIServer` verification strategies

[role="_abstract"]
Strategies for verifying the hub cluster `KubeAPIServer` certificate on managed clusters.

Managed clusters communicate with the hub cluster through a mutual connection with the {ocp-short} `KubeAPIServer` external load balancer. An internal {ocp-short} cluster certificate authority (CA) issues the default {ocp-short} `KubeAPIServer` certificate when you install {ocp-short}. The {mce-short} automatically detects and adds the certificate to managed clusters in the `bootstrap-kubeconfig-secret` namespace.

If your automatically detected certificate does not work, you can manually configure a strategy in the `KlusterletConfig` resource. Manual configuration controls how you verify the hub cluster `KubeAPIServer` certificate.

*Required access:* Cluster administrator

See the following strategies:

`UseAutoDetectedCABundle`::
The default configuration strategy. The {mce-short} automatically detects the certificate on the hub cluster and merges the certificate that is configured in the `trustedCABundles` list of config map references to the real CA bundles, if any exist.
+
The following example merges the automatically detected certificates from the hub cluster and the certificates that you configured in the `new-ocp-ca` config map, then adds both to the managed cluster:

+
[source,yaml]
----
apiVersion: config.open-cluster-management.io/v1alpha1
kind: KlusterletConfig
metadata:
 name: ca-strategy
spec:
 hubKubeAPIServerConfig:
   serverVerificationStrategy: UseAutoDetectedCABundle
   trustedCABundles:
   - name: new-ca
     caBundle:
       name: new-ocp-ca
       namespace: default
----

`UseSystemTruststore`::
When you set `UseSystemTruststore`, {mce-short} does not detect any certificate and ignores the certificates that are configured in the `trustedCABundles` specification. This configuration does not pass any certificate to the managed clusters. Instead, the managed clusters use certificates from the system trusted store to verify the hub cluster API server. Use this strategy when a public CA, such as Let's Encrypt, issues the hub cluster certificate.
+
See the following example:

+
[source,yaml]
----
apiVersion: config.open-cluster-management.io/v1alpha1
kind: KlusterletConfig
metadata:
 name: ca-strategy
spec:
 hubKubeAPIServerConfig:
   serverVerificationStrategy: UseSystemTruststore
----

`UseCustomCABundles`::
Use `UseCustomCABundles` when you know the CA of the hub cluster API server and you do not want {mce-short} to automatically detect it. For this strategy, {mce-short} adds your configured certificates from the `trustedCABundles` parameter to the managed clusters.
+
See the following example:

+
[source,yaml]
----
apiVersion: config.open-cluster-management.io/v1alpha1
kind: KlusterletConfig
metadata:
 name: ca-strategy
spec:
 hubKubeAPIServerConfig:
   serverVerificationStrategy: UseCustomCABundles
   trustedCABundles:
   - name: ca
     caBundle:
       name: ocp-ca
       namespace: default
----
+
Typically, this policy is the same for each managed cluster. As the hub cluster administrator, you can configure a `KlusterletConfig` named `global` to activate the policy for each managed cluster when you install {mce-short} or when the hub cluster certificate changes. See the following example:

+
[source,yaml]
----
apiVersion: config.open-cluster-management.io/v1alpha1
kind: KlusterletConfig
metadata:
 name: global
spec:
 hubKubeAPIServerConfig:
   serverVerificationStrategy: UseSystemTruststore
----
+
When a managed cluster needs a different strategy, create a different `KlusterletConfig` and use the `agent.open-cluster-management.io/klusterlet-config` annotation on the managed cluster to point to a specific strategy. See the following example:

+
[source,yaml]
----
apiVersion: config.open-cluster-management.io/v1alpha1
kind: KlusterletConfig
metadata:
 name: test-ca
spec:
 hubKubeAPIServerConfig:
   serverVerificationStrategy: UseCustomCABundles
   trustedCABundles:
   - name: ca
     caBundle:
       name: ocp-ca
       namespace: default
---
apiVersion: cluster.open-cluster-management.io/v1
kind: ManagedCluster
metadata:
  annotations:
    agent.open-cluster-management.io/klusterlet-config: test-ca
  name: cluster1
spec:
  hubAcceptsClient: true
  leaseDurationSeconds: 60
----
