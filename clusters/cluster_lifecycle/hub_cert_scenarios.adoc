[#hub-cert-update-scenarios]
= Hub cluster certificate update scenarios overview

[role="_abstract"]
The following scenarios describe which procedures to follow when you update the hub cluster certificate, depending on your configuration.

== Certificate renewal scenario

If you are renewing an expiring certificate, but both the intermediate and root CA are unchanged, complete steps in xref:../hub_cert_update.adoc#update-hub-kubeapi-cert[Updating the hub cluster _KubeAPIServer_ certificate].

This procedure applies to all strategies.

== New intermediate CA scenario

If you are moving to a certificate with a new intermediate CA, but the root CA is unchanged, select one of the following a procedures based on your strategy, and depending on whether your managed cluster already trusts the root CA or not:

- *_UseAutoDetectedCABundle_ strategy:*

* If the CA bundle currently used by the klusterlet includes the root CA, complete the steps in xref:../hub_cert_update.adoc#update-hub-kubeapi-cert[Updating the hub cluster _KubeAPIServer_ certificate].
* If the root CA is not in the CA bundle currently used by the klusterlet, complete the steps in xref:../hub_cert_root_ca.adoc#add-root-ca-klusterlet-ca[Adding a root CA to the klusterlet CA bundles].

- *_UseSystemTruststore_ strategy:*

* Complete the steps xref:../hub_cert_update.adoc#update-hub-kubeapi-cert[Updating the hub cluster _KubeAPIServer_ certificate].

- *_UseCustomCABundles_ strategy:*

* If the root CA is in your configured CA bundles, complete the steps in xref:../hub_cert_update.adoc#update-hub-kubeapi-cert[Updating the hub cluster _KubeAPIServer_ certificate].
* If the root CA is not in your configured CA bundles, complete the steps in xref:../hub_cert_root_ca.adoc#add-root-ca-klusterlet-ca[Adding a root CA to the klusterlet CA bundles].

== New root CA scenario

If you are moving to a certificate with a different root CA, select one of the following procedures based on your strategy, and whether your root CA is publicly trusted or not:

*Important:* Do not update the `KubeAPIServer` certificate directly when the root CA changes, or managed clusters might go offline immediately.

- *_UseAutoDetectedCABundle_ strategy:*

* Complete the steps in xref:../hub_cert_auto.adoc#update-root-ca-auto-ca[Updating the root CA with auto-detected CA bundles].

- *_UseSystemTruststore_ strategy:*

* If the new root CA is publicly trusted and present in all managed cluster system trust stores, complete the steps in xref:../hub_cert_update.adoc#update-hub-kubeapi-cert[Updating the hub cluster _KubeAPIServer_ certificate].
* If the new root CA is not publicly trusted, switch to `UseCustomCABundles` first by specifying the current CA bundle in a `ConfigMap`. Then, complete the steps in xref:../hub_cert_custom.adoc#update-root-ca-custom-ca[Updating the root CA with custom CA bundles].

-*_UseCustomCABundles_ strategy:*

* Complete the steps in xref:../hub_cert_custom.adoc#update-root-ca-custom-ca[Updating the root CA with custom CA bundles].
