[#proxy-intro]
= Cluster proxy

[role="_abstract"]
Configure proxy settings for {mce-short} so that you can create clusters, register managed clusters, and access managed cluster resources when a direct network path is not available.

You might need a proxy in the following situations:

* You create an {ocp} cluster when your hub cluster is connected through a proxy server. Configure the `cluster-wide-proxy` setting in your `install-config` YAML. See xref:../cluster_lifecycle/create_proxy_env.adoc#create-a-cluster-in-a-proxy-environment[Create a cluster in a proxy environment].
* Your managed cluster cannot reach the {mce-short} hub cluster directly. For example, the hub cluster is in a public cloud and the managed cluster is in a private cloud behind a firewall. Configure an HTTP or HTTPS proxy so that the managed cluster can access the hub cluster. See xref:../cluster_lifecycle/config_proxy_hub_managed.adoc#config-proxy-hub-managed[Configure the proxy between hub cluster and managed cluster].
* A managed cluster is behind a firewall and you cannot access it directly from the hub cluster. Enable and configure the cluster proxy add-on to access the managed cluster `kube-apiserver` with a more secure connection. The `cluster-proxy-addon` component automates the installation of `apiserver-network-proxy` on the hub and managed clusters by using a reverse proxy server.

*Note:* If the klusterlet agent on the managed cluster requires proxy settings to access the `apiserver` on the hub cluster instead of connecting directly, configure the proxy between the hub cluster and the managed cluster.
