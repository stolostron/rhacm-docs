[#gather-data-hub-token]
= Gather data with a hub cluster user token

[role="_abstract"]
Gather data with a hub cluster user token when the target hub cluster and target managed cluster both use the same external identity provider so that both clusters can recognize the same user.

.Prerequisites

* You must xref:../cluster_lifecycle/cluster_proxy_addon_settings.adoc#cluster-proxy-addon-settings[configure proxy settings for cluster proxy add-ons].

.Procedure

. To list pods in the default namespace by using the hub cluster `developer` user token, you must first create the correct `Role` and `RoleBinding` for the `developer` on the managed cluster.
+
If you are using {acm}, you can use the `ClusterPermission` API to create `Role` and `RoleBinding` objects from the hub cluster.

. Create a `ClusterPermission` that binds the `get` and `list` permissions for pods to the user `developer`. See the following example:

+
[source,yaml]
----
apiVersion: rbac.open-cluster-management.io/v1alpha1
kind: ClusterPermission
metadata:
  name: <name>
  namespace: <cluster-namespace>
spec:
  roles:
  - namespace: default
    rules:
    - apiGroups: [""]
      resources: ["pods"]
      verbs: ["get","list"]
  roleBindings:
  - namespace: default
    roleRef:
      kind: Role
    subject:
      apiGroup: rbac.authorization.k8s.io
      kind: User
      name: developer
----
