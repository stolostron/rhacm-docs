= Troubleshooting Microsoft Azure Red Hat OpenShift {hcp} cluster with Cluster API Provider for Azure becomes stuck during provisioning

When you create an Azure Red Hat OpenShift {hcp} cluster by using Cluster API Provider for Azure, the cluster status might become stuck during provisioning.

== Symptom: Microsoft Azure Red Hat OpenShift {hcp} cluster with Cluster API Provider for Azure becomes stuck during provisioning

Azure Red Hat OpenShift {hcp} clusters with Cluster API Provider for Azure become stuck during provisioning. The cluster status might be _Provisioning_ or _Provisioned_, but the cluster is not available for use.

== Resolving the problem: Microsoft Azure Red Hat OpenShift {hcp} cluster with Cluster API Provider for Azure becomes stuck during provisioning

To begin troubleshooting, you need additional information about the cluster status and conditions, infrastructure status, Azure Service Operator resource status, and events. Complete the following steps to get more information:

. Check the cluster status and conditions. Run the following command. Replace `<cluster-name>` and `<cluster-namespace>` with the name and namespace of your cluster:

+
[source,bash]
---- 
clusterctl describe cluster <cluster-name> -n <cluster-namespace> --show-conditions=all
----

. Check the infrastructure status. Run the following command. Replace `<cluster-name>` and `<cluster-namespace>` with the name and namespace of your cluster:

+
[source,bash]
----
oc get arocluster <cluster-name> -n <cluster-namespace> -o yaml | yq '.status'
----

. Check the Azure Service Operator resource status. Run the following command. Replace `<cluster-name>` and `<cluster-namespace>` with the name and namespace of your cluster:

+
[source,bash]
----
oc get HcpOpenShiftCluster <cluster-name> -n <cluster-namespace> -o yaml | yq '.status.conditions'
----

. Check for errors in events. Run the following command. Replace `<cluster-namespace>` and `<cluster-name>` and  with the namespace and name of your cluster:

+
[source,bash]
----
oc get events -n <cluster-namespace> --sort-by='.lastTimestamp' | grep <cluster-name>
----
