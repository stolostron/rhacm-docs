[#upgrade-managed-missing-ocp]
= Troubleshooting upgraded managed cluster with missing {ocp-short} version 

After you upgrade your managed cluster, the expected {ocp-short} version is missing.

[#symptom-missing-ocp]
== Symptom: After managed cluster upgrade the {ocp-short} version is missing 

After you upgraded your managed cluster, you did not see the {ocp-short} version that you want in the console.

[#resolve-missing-ocp]
== Resolving the problem: After managed cluster upgrade the {ocp-short} version is missing 

See the following procedure:

. Ensure the desired version is included in the status of the `ClusterVersion` on the managed cluster. Run the following command:

+
[source,bash]
----
oc get clusterversion version -o jsonpath='{.status.availableUpdates[*].version}'
----

+
If your expected version is not displayed, then the version is not applicable for this managed cluster.

. Check if the `ManagedClusterInfo` includes the desired version on the hub cluster. Run the following command:

+
[source,bash]
----
oc -n <cluster_name> get managedclusterinfo <cluster_name> -o jsonpath='{.status.distributionInfo.ocp.availableUpdates[*]}'
----

. If the version is included, check to see if there is a `ClusterCurator` with failure on the hub cluster. Run the following command:

+
[source,bash]
----
oc -n <cluster_name> get ClusterCurator local-cluster -o yaml
----

. If the `ClusterCurator` exists and the status of its `clustercurator-job` condition is `False`, delete the `ClusterCurator` from the hub cluster. Run the following command:

+
[source,bash]
----
oc -n <cluster_name> delete ClusterCurator local-cluster
----

. If the `ManagedClusterInfo` does not include the desired version, check the `work-manager` add-on log on the managed cluster and fix errors that are reported.

+
[source,bash]
----
oc -n open-cluster-management-agent-addon logs klusterlet-addon-workmgr-xxx-xx
----

. Replace the pod name with the real name in your environment.
