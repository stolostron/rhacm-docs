[#mce-network-configuration]
= Network configuration

Configure your network settings to allow the connections.

**Important:** The trusted CA bundle is available in the {mce-short} namespace, but that enhancement requires changes to your network. The trusted CA bundle ConfigMap uses the default name of `trusted-ca-bundle`. You can change this name by providing it to the operator in an environment variable named `TRUSTED_CA_BUNDLE`. See link:https://access.redhat.com/documentation/en-us/openshift_container_platform/4.14/html/networking/enable-cluster-wide-proxy#nw-proxy-configure-object_config-cluster-wide-proxy[Configuring the cluster-wide proxy] in the _Networking_ section of {ocp} for more information.

*Note:* `Registration Agent` and `Work Agent` on the managed cluster do not support proxy settings because they communicate with `apiserver` on the hub cluster by establishing an mTLS connection, which cannot pass through the proxy.

For the {mce-short} cluster networking requirements, see the following table:

.Table list of networking requirements
|===
| Direction | Source | Destination | Protocol | Port | Description

| Outbound to the managed cluster
| Hive and `import-controller` on the hub cluster
| Kubernetes API server of the provisioned managed cluster
| HTTPS
| 6443
| The Kubernetes API server of the provisioned managed cluster

| Outbound to the managed cluster
| Ironic service on the hub cluster
| Ironic Python Agent on the managed cluster
| TCP
| 9999
| Communication between the bare metal node where the Ironic Python Agent is running and the Ironic conductor service

| Inbound from the managed cluster
| Baseboard Management Controller (BMC)
| HTTP server next to the Ironic service
| TCP
| 6180, 6183
| The Baseboard Management Controller (BMC) accesses port 6180 and 6183 for virtual media. The boot firmware accesses port 6180.

| Inbound from the managed cluster
| Ironic Python Agent on the managed cluster
| Ironic service on the hub cluster
| TCP
| 6385
| Communication between the Ironic Python Agent and the Ironic service on the hub cluster.

| Inbound from the managed cluster
| Cluster proxy add-on agent on the managed cluster
| Cluster proxy ANP service
| TCP
| 443
| Communication between the cluster proxy add-on agent on the managed cluster and the Cluster Proxy add-on ANP service on the hub cluster

| Inbound from the managed cluster
| Klusterlet agent and add-on agents
| Kubernetes API server on the hub cluster
| HTTPS
| 6443
| The Kubernetes API server of the {mce-short} cluster from the managed cluster

|===

*Note:* The managed cluster must be able to reach the hub cluster control plane node IP addresses.
