= Creating a credential for {aap-short}

[role="_abstract"]
You need a credential to use {mce-short} console to deploy and manage an {ocp} cluster that is using Red Hat {aap-short}. This procedure must be done before you can create an Automation template to enable automation on a cluster.

*Required access:* Edit

.Prerequisites

* A deployed {mce-short} hub cluster.
* Ansible login credentials, which includes {aap-short} hostname and OAuth token; see link:https://docs.ansible.com/ansible-tower/latest/html/userguide/credentials.html[Credentials for {aap-short}].
* Account permissions that allow you to install hub clusters and work with Ansible. Learn more about link:https://docs.ansible.com/ansible-tower/latest/html/userguide/users.html[Ansible users].

.Procedure

. In the console, click *Credentials* to choose from existing credential options. 

. Create a namespace specifically to host your credentials, both for convenience and added security.

+
*Important:* The Ansible Token and host URL that you provide when you create your Ansible credential are automatically updated for the automation that use that credential when you edit the credential. The updates are copied to any automations that use that Ansible credential, including those related to cluster lifecycle, governance, and application management automations. This ensures that the automations continue to run after the credential is updated. 

. Edit your credential in the console. Ansible credentials are automatically updated in your automation that use that credential when you update them in the credential.

. Create an Ansible Job that uses this credential by completing the steps in xref:../cluster_lifecycle/ansible_config_cluster.adoc#ansible-config-cluster[Configuring {aap-short} tasks to run on managed clusters].

. Delete the credential when you are no longer managing that cluster to protect the information in the credential. Select *Actions* to delete in bulk, or select the options menu beside the credential that you want to delete.
