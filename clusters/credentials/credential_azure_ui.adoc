= Creating a credential for Microsoft Azure in the console 

[role="_abstract"]
You need a credential to use {mce-short} console to create and manage a {ocp} cluster on Microsoft Azure or on Microsoft Azure Government. You can also create a credential for Microsoft Azure with the API. See xref:../credentials/credential_azure_api.adoc#creating-credential-azure-api[Creating a credential for Microsoft Azure with the API] for those steps.

*Required access:* Edit

*Note:* This procedure is a prerequisite for creating a cluster with {mce-short}.

.Prerequisites

* A deployed {mce-short} hub cluster.
* Internet access for your {mce-short} hub cluster so that it can create the Kubernetes cluster on Azure.
* Azure login credentials, which include your Base Domain Resource Group and Azure Service Principal JSON. See _Microsoft Azure portal_ to get your login credentials.
* Account permissions that allow installing clusters on Azure. See _How to configure Cloud Services_ and _Configuring an Azure account_ for more information.

.Procedure

. In the console, click *Credentials* to choose from existing credential options. 
. Create a namespace specifically to host your credentials, both for convenience and added security.

. *Optional:* Add a _Base DNS domain_ for your credential. If you add the base DNS domain to the credential, it is automatically populated in the correct field when you create a cluster with this credential.

. Select whether the environment for your cluster is `AzurePublicCloud` or `AzureUSGovernmentCloud`. The settings are different for the Azure Government environment, so ensure that this is set correctly. 

. Add your _Base domain resource group name_ for your Azure account. This entry is the resource name that you created with your Microsoft Azure account. You can find your Base Domain Resource Group Name by selecting *Home* > *DNS Zones* in the Azure interface. See _Create an Azure service principal with the Azure CLI_ to find your base domain resource group name.

. Provide the contents for your _Client ID_. This value is generated as the `appId` property when you create a service principal with the following command. Replace `<service_principal>` with the name of your service principal:

+
[source,bash]
----
az ad sp create-for-rbac --role Contributor --name <service_principal> --scopes <subscription_path>
----

. Add your _Client Secret_. This value is generated as the `password` property when you create a service principal. Run the following command and replace <service_principal> with the name of your service principal:

+
[source,bash]
----
az ad sp create-for-rbac --role Contributor --name <service_principal> --scopes <subscription_path>
----

. Add your _Subscription ID_. This value is the `id` property in the output of the following command:

+
[source,bash]
----
az account show
----

. Add your _Tenant ID_. This value is the `tenantId` property in the output of the following command:

+
[source,bash]
----
az account show
----

. If you want to enable a proxy, enter the proxy information: 

. Enter your _Red Hat OpenShift pull secret_. See _Download your Red Hat OpenShift pull secret_ to download your pull secret.

. Add your _SSH private key_ and _SSH public key_ to use to connect to the cluster. You can use an existing key pair, or create a new pair using a key generation program.

. Create a cluster that uses this credential by completing the steps in _Creating a cluster on Microsoft Azure_.

. Edit your credential in the console as needed. 

. Delete the credential when you are no longer managing that cluster to protect the information in the credential. Select *Actions* to delete in bulk, or select the options menu beside the credential that you want to delete.
