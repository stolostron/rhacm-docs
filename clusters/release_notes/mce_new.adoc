= New features and enhancements for Cluster lifecycle with {mce-short}

Learn about {mce} 2.10 new features and enhancements, support, deprecations, removals, and fixed issues for errata releases. 

{mce-short} version 2.10 is released with {acm-short} version 2.15 for Cluster lifecycle management, but you can use stand-alone {mce-short} with your {ocp-short} hub cluster, as well. 

For full support information, including supported {ocp-short} versions, see the link:https://access.redhat.com/articles/7133096[{mce-short} Support Matrix]. For lifecycle information, see link:https://access.redhat.com/support/policy/updates/openshift[{ocp} Life Cycle policy].

Use {mce-short} features for creating, importing, managing, and destroying Kubernetes clusters across various infrastructure cloud providers, private clouds, and on-premises data centers.

*Important:* 

- Cluster management supports all providers that are certified through the Cloud Native Computing Foundation (CNCF) Kubernetes Conformance Program. Choose a vendor that is recognized by CNCF for your hybrid cloud multicluster management. See the following information about using CNCF providers:

- Learn how CNCF providers are certified at link:https://www.cncf.io/training/certification/software-conformance/[Certified Kubernetes Conformance].

- For Red Hat support information about CNCF third-party providers, see link:https://access.redhat.com/articles/third-party-software-support[Red Hat support with third party components], or link:https://access.redhat.com/support/contact/[Contact Red Hat support].

- If you bring your own CNCF conformance certified cluster, you need to change the {ocp-short} CLI `oc` command to the Kubernetes CLI command, `kubectl`.

Learn about new features and enhancements that come with the {mce-short} installation:

Learn about new features and enhancements for Cluster lifecycle with {mce-short}:

- *Technology Preview:* Automatically import clusters that you provision by using Cluster API to save time when importing. See xref:../cluster_api/auto_import_capi.adoc#auto-import-capi[Enabling automatic import for Cluster API clusters (Technology Preview)] to learn more.
- *Technology Preview:* Switch from Amazon Web Services credentials to Identity and Access Management roles so that you can create {rosa-hcp} clusters without storing AWS credentials on your managed cluster. See xref:../cluster_api/switch_iam_roles.adoc#switch-iam-roles-capi[Switching from AWS credentials to IAM roles on your Cluster API managed cluster (Technology Preview)] to learn more.
- *Technology Preview:* Provision and manage the lifecycle of a {rosa-hcp} cluster with Cluster API so that you can use a GitOps approach to cluster liffecycle at scale. See xref:../cluster_api/create_capi_rosa.adoc#create-rosa-hcp-capi-cluster[Creating a {rosa-hcp} cluster with Cluster API (Technology Preview)] to learn more.
- You can now define managed namespaces for `ManagedClusterSet` resources to manage and scale clusters efficiently, or to apply configurations consistently across your fleet. See xref:../cluster_lifecycle/set_managed_ns.adoc#set-managed-ns[Setting managed namespaces for _ManagedClusterSets_].
- You can now install a two-node with fencing cluster to ensure redundancy at the edge and limit hardware costs. See xref:../assisted_installer/ai_install_tnf.adoc#install-tnf-cluster-ai[Installing a two-node with fencing cluster with {ai} (Technology Preview)] to learn more.

If you are using {mce-short} with {acm-short} installed afterwards, see the link:../../release_notes/acm_new.adoc#new-features-acm[New features and enhancements for {acm-short}] this release.
