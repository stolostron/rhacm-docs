[#whats-new-mce]
= What's new for Cluster lifecycle with {mce-short}

Learn about new {mce} features for creating, importing, managing, and destroying Kubernetes clusters across various infrastructure cloud providers, private clouds, and on-premises data centers.

{mce-short} version 2.8 is released with {acm-short} version 2.13 for Cluster lifecycle management, but you can use {mce-short} with your {ocp-short} hub cluster, as well. 

For full support information, including supported {ocp-short} versions, see the link:https://access.redhat.com/articles/7099674[{mce-short} Support matrix]. For lifecycle information, see link:https://access.redhat.com/support/policy/updates/openshift[{ocp} Life Cycle policy].

*Important:* Cluster management supports all providers that are certified through the Cloud Native Computing Foundation (CNCF) Kubernetes Conformance Program. Choose a vendor that is recognized by CNFC for your hybrid cloud multicluster management.

See the following information about using CNFC providers:

* Learn how CNFC providers are certified at link:https://www.cncf.io/training/certification/software-conformance/[Certified Kubernetes Conformance].

* For Red Hat support information about CNFC third-party providers, see link:https://access.redhat.com/third-party-software-support[Red Hat support with third party components], or link:https://access.redhat.com/support/contact/[Contact Red Hat support].

* If you bring your own CNFC conformance certified cluster, you need to change the {ocp-short} CLI `oc` command to the Kubernetes CLI command, `kubectl`.

[#mce-install-new]
== Installation

Learn about new features and enhancements that come with the {mce-short} installation.

You can now change the name of your local cluster. By default, the cluster that is running {mce-short} is the _local cluster_, which is a hub cluster that manages itself. When the `enabled` field is set to `false`, which disables the local cluster feature, you can change the name. Use 34 or fewer characters for the `<your-local-cluster-name>` value. The `local-cluster` resource and the namespaces reflects the change.

[#cluster-management-new]
== Cluster management

Learn about new features and enhancements for Cluster lifecycle with {mce-short}.

- You can now define a unique mirror registry for each cluster. To learn more, see xref:../assisted_installer#config-mirror-reg-cluster[Configuring mirror registries for each cluster].
- You can now customize the automatic import strategy of managed clusters. To learn more, see xref:../cluster_lifecycle/adv_config_cluster.adoc#custom-auto-import-strat[Customizing the automatic import strategy].
- You can now filter discovered clusters by cluster type and infrastructure provider in the console. To learn more, see xref:../discovery/discovery_config_ui.adoc#discovery-view[View discovered clusters].
- You can now use any file name for the `OSImageCACert` `ConfigMap`.
