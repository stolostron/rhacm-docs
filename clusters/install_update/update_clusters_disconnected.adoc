= Updating clusters in a disconnected environment

[role="_abstract"]
You can view a list of available updates for your managed cluster. You can use the {acm-short} console to select a channel for your cluster updates on {ocp-short}. Those versions must be available on the mirror registry. After configuring the disconnected registry, {acm-short} and {update-service} use the disconnected registry to find if updates are available.

After configuring the disconnected registry, {acm-short} and {update-service} use the disconnected registry to find if updates are available. See link:https://docs.redhat.com/en/documentation/openshift_container_platform/4.20/html/registry/configuring-registry-operator#images-configuration-cas_configuring-registry-operator[Configuring additional trust stores for image registry access] in the {ocp-short} documentation to learn more about the external registry CA certificate.

If no available updates are displayed, make sure that you have the release image of the current level of the cluster and at least one later level mirrored in the local repository.

If the release image for the current version of the cluster is not available, no updates are available.

.Procedure

. From the console, select *Infrastructure* > *Clusters*.

. Select a cluster that is in the _Ready_ state.

. From the *Actions* menu, select *Update cluster*. 

. Verify that the optional update paths are available. *Note:* No available update versions are shown if the current version is not mirrored into the local image repository.  

. Select a _channel_ for your cluster updates on {ocp-short}. Those versions must be available on the mirror registry.

. In the console, select *Infrastructure* > *Clusters*.

. Find the cluster that you want to update. If there is an update available, the *Distribution version* column for the cluster displays an update available. 

. Select the _Options_ menu for that cluster, and select *Update cluster*.

. Select the target version for the update, and select *Update*. 

If your cluster update fails, the Operator generally retries the update a few times, stops, and reports the status of the failing component. In some cases, the update process continues to cycle through attempts to complete the process. Rolling your cluster back to a previous version after a failed update is not supported. Contact Red Hat support for assistance if your cluster update fails.
