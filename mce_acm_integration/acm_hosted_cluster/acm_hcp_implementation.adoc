= Implementation considerations

[role="_abstract"]
Learn about the process and gather other important information for fleet management architecture.

* The central {acm-short} hub cluster manages both the {mce-short} clusters and the attached {hcp} clusters
* Policies and governance are applied consistently across the entire infrastructure.
* Monitoring and alerting are centralized while hosting capacity remains distributed.

See the following process overview:

Deploy the central {acm-short} hub cluster:: Establish this cluster as your primary management interface.
Deploy {mce-short} clusters:: Use these as the hosting infrastructure for your control planes.
Configure discovery:: Ensure the {acm-short} hub cluster can manage both the {mce-short} clusters and the attached {hcp} clusters.

*Important:* A {acm-short} cluster cannot manage another {acm-short} cluster.

If you have already deployed multiple {acm-short} hub clusters to host control planes, use the following process for this pattern architecture:

Convert {acm-short} hosting clusters to {mce-short}:: Uninstall {acm-short} and install {mce-short} on the clusters that are designated for hosting infrastructure.
Preserve {hcp} clusters:: Ensure the conversion process does not disrupt existing {hcp} clusters.
Designate the hub cluster:: Select one {acm-short} cluster to serve as the central management hub cluster.
