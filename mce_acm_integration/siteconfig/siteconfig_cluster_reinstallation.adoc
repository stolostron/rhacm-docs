= Cluster reinstallation with the {sco} (Technology Preview)

[role="_abstract"]
The {sco} simplifies OpenShift cluster reinstallation through the `ClusterInstance` API while preserving critical configuration data.

With a GitOps-compatible, declarative approach, users can begin reinstallations by updating the `ClusterInstance` resource. The operator also includes a backup and restore mechanism for hub-side `Secret` and `ConfigMap` resources, ensuring essential cluster data, such as authentication credentials and configuration resources, remains intact.

* Cluster identity preservation: Cluster reinstallation supports both {sno} and multi-node OpenShift clusters. However, cluster identity preservation is only supported for {sno} clusters installed using the Image Based Install provisioning method. For more information about the Image Based Install, see link:https://docs.redhat.com/en/documentation/openshift_container_platform/4.20/html/edge_computing/image-based-installation-for-single-node-openshift#deploying-single-node-openshift-clusters[Image-based installation for {sno}].

See the following steps of the cluster reinstallation workflow:

* Label resources for preservation. This is optional if you do not want to preserve resources. You can label your resources well before initiating the cluster reinstallation.
* Initiate a cluster reinstallation.
* Monitor the reinstallation progress and verify that the reinstalled cluster is available. This is optional.
