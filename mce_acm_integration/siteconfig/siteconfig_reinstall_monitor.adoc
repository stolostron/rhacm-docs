[#monitor-cluster-reinstallation]
= Monitor the cluster reinstallation

[role="_abstract"]
Monitor the cluster reinstallation progress. You can monitor the cluster reinstallation progress. Complete the following steps.

*Required access:* Cluster administrator

.Procedure

. Verify that the reinstallation request is being processed. Run the following command:

+
[source,bash]
----
oc get clusterinstance clusterinstance-example -n some-namespace -o json | jq -r '.status.reinstall.conditions[] | select(.type=="ReinstallRequestProcessed")'
----

+
See the following example output:

+
[source,json]
----
{
"type": "ReinstallRequestProcessed"
"reason": "InProgress",
"status": "False",
...
}
----

. Verify that the cluster reinstallation request is validated successfully. Run the following command:

+
[source,bash]
----
oc get clusterinstance clusterinstance-example -n some-namespace -o json | jq -r '.status.reinstall.conditions[] | select(.type=="ReinstallRequestValidated")'
----

+
See the following example output:

+
[source,json]
----
{
"type": "ReinstallRequestValidated"
"reason": "Completed",
"status": "True",
...
}
----

. Optional. If you set the `spec.reinstall.preservationMode` field to `All` or `ClusterIdentity`, verify that the cluster identity data is preserved. Run the following command:

+
[source,bash]
----
oc get clusterinstance clusterinstance-example -n some-namespace -o json | jq -r '.status.reinstall.conditions[] | select(.type=="ReinstallPreservationDataBackedup")'
----

+
See the following example output:

+
[source,json]
----
{
"type": "ReinstallPreservationDataBackedup"
"reason": "Completed",
"status": "True",
...
}
----

. *Optional:* If you set the `spec.reinstall.preservationMode` field to `All` or `ClusterIdentity`, you can verify that the cluster identity data is detected. Run the following command:

+
[source,bash]
----
oc get clusterinstance clusterinstance-example -n some-namespace -o json | jq -r '.status.reinstall.conditions[] | select(.type=="ReinstallClusterIdentityDataDetected")'
----

+
See the following example output:

+
[source,json]
----
{
"type": "ReinstallClusterIdentityDataDetected"
"reason": "DataAvailable",
"status": "True",
...
}
----

. Verify that the installation manifests are deleted. The deletion can take several minutes to complete. Run the following command:

+
[source,bash]
----
oc get clusterinstance clusterinstance-example -n some-namespace -o json | jq -r '.status.reinstall.conditions[] | select(.type=="ReinstallRenderedManifestsDeleted")'
----

+
See the following example output:

+
[source,json]
----
{
"type": "ReinstallRenderedManifestsDeleted"
"reason": "Completed",
"status": "True",
...
}
----

. *Optional:* If you set the `preseservationMode` field to `All` or `ClusterIdentity`, you can verify that the data preserved earlier are restored. Run the following command:

+
[source,bash]
----
oc get clusterinstance clusterinstance-example -n some-namespace -o json | jq -r '.status.reinstall.conditions[] | select(.type=="ReinstallPreservationDataRestored")'
----

+
See the following example output:

+
[source,json]
----
{
"type": "ReinstallPreservationDataRestored"
"reason": "Completed",
"status": "True",
...
}
----

. Ensure that the reinstallation request completed successfully. Run the following command:

+
[source,bash]
----
oc get clusterinstance clusterinstance-example -n some-namespace -o json | jq -r '.status.reinstall.conditions[] | select(.type=="ReinstallRequestProcessed")'
----

+
See the following example output:

+
[source,json]
----
{
"type": "ReinstallRequestProcessed"
"reason": "Completed",
"status": "True",
...
}
----

. Confirm that the cluster is successfully reinstalled and is operational by running an `oc` command with the `kubeconfig` file that is associated with the reinstalled cluster.
