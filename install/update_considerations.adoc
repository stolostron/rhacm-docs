[#update-considerations]
=  Update considerations for your hub cluster

[role="_abstract"]
Before you update your {acm} hub cluster, see the following information about the update process and requirements, then proceed to xref:./update_hub.adoc#updating-hub[Updating your hub cluster] for instructions about how to update your hub cluster.

*Required access:* {ocp-short} administrator

* Plan to update both {acm-short} and {mce-short}. Do not attempt to update {mce-short} separately from {acm-short} update because this action can cause issues with your cluster.

* If you attempt to update to an unsupported {ocp-short} version, you receive an error message. If you force the update to an _unsupported_ version, your {acm-short} hub cluster does not function correctly.

* When you update {acm-short}, {mce-short} automatically updates to the required version. The `MultiClusterHub` `mceVersionCompliance` resource status is `isCompliant: true`. 

* Updates are always supported from the immediate previous version. You can update to the next available feature release. 

* If you are on a version with _Extended Update Support_ (EUS), you can update to the next version, or you can skip to the next EUS version. You can perform skip-level updates from `<2.x>` to `<2.x+2>` on _odd_ number versions of {acm-short}. For instance, when you update {acm-short} 2.13, which is an EUS version, you can choose to update to version 2.15, which is also an EUS version.

* Downgrading a version is not supported. You cannot revert to an earlier version after updating to a later version in the channel selection. You must uninstall the operator and reinstall it with the earlier version to use a previous version.

* The {olm} `operatorcondition` helps control how versions are updated. When you initially deploy {acm-short} by using the operator, you make the following selections:

+
Channel:: Channel corresponds to the version of the product that you are installing. The initial channel setting is often the most current channel that was available at the time of installation. 
Approval:: Approval specifies whether approval is required for updates within the channel, or if they are done automatically. 

+
* If set to `Automatic`, then minor release updates in the selected channel are deployed without administrator intervention. 
+
- If set to `Manual`, then each update to the minor release within the channel requires an administrator to approve the update. 
+
You also use these settings when you update to the latest version of {acm-short} by using the operator. 

Continue to xref:./update_hub.adoc#updating-hub[Updating your hub cluster] to complete the steps to update your operator.
