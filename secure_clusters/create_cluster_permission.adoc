[#create-cluster-permission]
= Creating a cluster permission 

[role="_abstract"]
When the service account is created there are no associated permissions. To grant permissions to the new service account, use the `ClusterPermission` resource. Create the `ClusterPermission` resource in the managed cluster namespace on the hub cluster. Use the `ClusterPermission` resource to create roles, cluster roles resources on the managed clusters, and bind them to a service account through a `RoleBinding` or `ClusterRoleBinding` resource.

*Required access:* Cluster administrator

.Prerequisites

* If you want to bind to the `ManagedServiceAccount` resource, you must have the `ManagedServiceAccount` add-on. For more information about enabling the `ManagedServiceAccount` add-on, see link:../add-ons/configure_klusterlet_addons.adoc[Configuring klusterlet add-ons]. 

.Procedure 

. To grant the `<managed-sa-sample>` service account permission to the sample mortgage application that is deployed to the `mortgage` namespace on `<managed-cluster>`, create a YAML file that includes the following specifications, `roles`, `clusterRole`, `roleBindings` and `clusterRoleBinding`.
.. Add a role in the `default` namespace and the `mortgage` namespace. The following partial example includes a role named, `<clusterpermission-msa-subject-sample>`. Your `roles` specification for your `ClusterPermission` resource might resemble the following example:

+
[source,yaml]
----
apiVersion: rbac.open-cluster-management.io/v1alpha1
kind: ClusterPermission
metadata:
  name: <clusterpermission-msa-subject-sample>
  namespace: <managed-cluster>
spec:
  roles:
  - namespace: default
    rules:
    - apiGroups: ["apps"]
      resources: ["deployments"]
      verbs: ["get", "list", "create", "update", "delete", "patch"]
    - apiGroups: [""]
      resources: ["configmaps", "secrets", "pods", "podtemplates", "persistentvolumeclaims", "persistentvolumes"]
      verbs: ["get", "update", "list", "create", "delete", "patch"]
    - apiGroups: ["storage.k8s.io"]
      resources: ["*"]
      verbs: ["list"]
  - namespace: mortgage
    rules:
    - apiGroups: ["apps"]
      resources: ["deployments"]
      verbs: ["get", "list", "create", "update", "delete", "patch"]
    - apiGroups: [""]
      resources: ["configmaps", "secrets", "pods", "services", "namespace"]
      verbs: ["get", "update", "list", "create", "delete", "patch"]
----

.. Add a `clusterRole` specification to your `ClusterPermission` resource. Your YAML file might resemble the following example:

+
[source,yaml]
----
  clusterRole:
    rules:
    - apiGroups: ["*"]
      resources: ["*"]
      verbs: ["get", "list"]
----

.. Add the `roleBindings` specifications to your `ClusterPermission` resource for binding the role to the managed service account. Your YAML file might resemble the following example:

+
[source,yaml]
----
  roleBindings:
  - namespace: default
    roleRef:
      kind: Role
    subject:
      apiGroup: authentication.open-cluster-management.io
      kind: ManagedServiceAccount
      name: <managed-sa-sample>
  - namespace: mortgage
    roleRef:
      kind: Role
    subject:
      apiGroup: authentication.open-cluster-management.io
      kind: ManagedServiceAccount
      name: <managed-sa-sample>
----

.. Add the `clusterRoleBinding` specification to your `ClusterPermission` resource for binding the `ClusterRole` to the managed service account. Your YAML file might resemble the following example:

+
[source,yaml]
----
  clusterRoleBinding:
    subject:
      apiGroup: authentication.open-cluster-management.io
      kind: ManagedServiceAccount
      name: <managed-sa-sample>
----

. Save your YAML file.

. Apply your YAML file by running the following command:

+
[source,bash]
----
oc apply -f cluster-permission.yaml
----

. The sample `<clusterpermission>` creates a role called `<clusterpermission-msa-subject-sample>` in the `mortgage` namespace. If one does not already exist, create a namespace `mortgage`. 
. Review the resources that are created on the `<managed-cluster>` namespace.
