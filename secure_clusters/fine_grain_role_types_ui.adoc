= Fleet Management role assignments overview

In {acm-short}, role assignments define how identities, such as users or groups, interact with your fleet. Understanding the scope of these assignments is essential for maintaining a secure, multi-tenant environment. See the following sections for details on the different scopes and how to manage role assignments effectively.

* Granularity: Cluster versus project role assignments

Before you create a role assignment, determine the appropriate scope for the identity. The level of granularity ensures that users have the necessary permissions without compromising cluster security.

* **Cluster role assignment**: Grants the identity access to all namespaces within the targeted clusters or cluster sets. Use this scope for cluster administrators or infrastructure operators who require global visibility and control.
* **Project role assignment**: Enforces a strict security boundary by granting access only to specific projects (namespaces) within clusters or cluster sets. Use this scope for application development teams or line-of-business users in a multi-tenant environment.


* Method: Accessing role assignments

You can manage role assignments through several paths in the Red Hat Advanced Cluster Management console. The path you choose depends on whether you are managing global infrastructure or specific application resources.

To begin, navigate to **Fleet Management** in the console. From there, select one of the following methods:

|===
| Method | Use case

| **Clusters**
| Use this path to manage roles for a specific managed cluster.

| **Cluster sets**
| Use this path to manage roles for a logical group of clusters.

| **Projects**
| Use this path to assign roles to specific namespaces across your fleet.

| **Namespace**
| Use this path for granular control over a single namespace on a specific cluster.
|===

[IMPORTANT]
====
Role assignments are additive. If a user is granted a role at the cluster set level and a different role at the project level, they inherit the permissions of both assignments.
====
