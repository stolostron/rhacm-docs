[#fine-grain-mca-custom]
= Managing custom roles with _MulticlusterRoleAssignment_

Beyond the built-in fine-grained RBAC roles for virtualization, you can create custom `ClusterRole` resources to define environment-specific permissions. Use custom roles when built-in options do not meet your access requirements, such as granting console-only access to virtual machines without lifecycle control. 

Ensure the custom role exists on each managed cluster before the assignment. Create the custom`ClusterRole`, distribute it by using a governance policy, and assign it through `MultiClusterRoleAssignment` resources.

*Required access:* Cluster administrator

. Prerequisites

* Enable fine-grained role-based access control. See _Enabling fine-grained role-based access control for virtualization_ for the procedure.
* Ensure that the governance policy framework is enabled on your hub cluster.
* Ensure you have a `Placement` resource that targets the desired managed clusters.
* The hub cluster user must have the `acm-vm-fleet:view` `ClusterRole` bound on the hub cluster. To create a `ClusterRoleBinding` on the hub cluster to grant this role see xref:../secure_clusters/fine-grain-roles-descriptions.adoc#fine-grain-roles-descriptions[Fine-grained RBAC roles and descriptions].
* Learn about the following custom role labeling requirements:

+
** *Label:* `rbac.open-cluster-management.io/filter`
*** *Value:* `vm-clusterroles`
** *Label:* `clusterview.open-cluster-management.io/discoverable`
*** *Value:* `"true"`
** *Label:* `rbac.open-cluster-management.io/custom-role`
*** *Value:* `"true"`

.Procedure

. Create a YAML file that defines your custom `ClusterRole`. The following example creates a role that is named `kvm-console-only` to grant read-only access to virtual machines and the VNC console:

+
[source,yaml]
----
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata: 
  name: kvm-console-only 
  labels: 
    rbac.open-cluster-management.io/filter: vm-clusterroles 
    clusterview.open-cluster-management.io/discoverable: "true" 
    rbac.open-cluster-management.io/custom-role: "true"
rules: 
  - apiGroups: ["kubevirt.io"] 
    resources: ["virtualmachines", "virtualmachineinstances"] 
    verbs: ["get", "list", "watch"] 
  - apiGroups: ["subresources.kubevirt.io"] 
    resources: 
      - virtualmachineinstances/vnc 
    verbs: ["get"]
----

. Apply the resource on the hub cluster by running the following command:

+
[source,bash]
----
oc apply -f <your-custom-clusterrole>.yaml
----

. Automatically propagate custom roles from the hub cluster to all managed clusters by using a policy. The policy discovers any `ClusterRole` with the `rbac.open-cluster-management.io/custom-role: "true"` label on the hub cluster and enforces the existence of those roles on the managed clusters.

.. Create a `ServiceAccount` with permission to list cluster-scoped resources on the hub cluster. The policy uses this service account to discover custom roles. Create a YAML file that is named `hub-service-account.yaml` with the following content:

+
[source,yaml]
----
apiVersion: v1
kind: ServiceAccount
metadata: 
  name: policy-hub-clusterroles 
  namespace: open-cluster-management-global-set
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata: 
  name: open-cluster-management:policy-hub-clusterroles
rules: 
  - apiGroups: ["rbac.authorization.k8s.io"] 
    resources: ["clusterroles", "roles"] 
    verbs: ["list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata: 
  name: policy-hub-clusterroles-binding
roleRef: 
  apiGroup: rbac.authorization.k8s.io 
  kind: ClusterRole 
  name: open-cluster-management:policy-hub-clusterroles
subjects: 
  - kind: ServiceAccount 
    name: policy-hub-clusterroles 
    namespace: open-cluster-management-global-set
----

.. Apply the file to your hub cluster by running the following command:

+
[source,bash]
----
oc apply -f hub-service-account.yaml
----

.. Create the `Policy` resource YAML file that is named `policy-custom-vm-roles.yaml` with the following content:

+
[source,yaml]
----
apiVersion: policy.open-cluster-management.io/v1
kind: Policy
metadata:
  name: policy-custom-vm-roles
  namespace: open-cluster-management-global-set
spec:
  disabled: false
  remediationAction: enforce
  hubTemplateOptions:
    serviceAccountName: policy-hub-clusterroles
  policy-templates:
    - objectDefinition:
        apiVersion: policy.open-cluster-management.io/v1
        kind: ConfigurationPolicy
        metadata:
          name: custom-vm-roles
        spec:
          remediationAction: enforce
          severity: medium
          object-templates-raw: |
            {{hub- range $role := (lookup "rbac.authorization.k8s.io/v1" "ClusterRole" "" "" "rbac.open-cluster-management.io/custom-role=true").items hub}}
            - complianceType: musthave
              objectDefinition:
                apiVersion: rbac.authorization.k8s.io/v1
                kind: ClusterRole
                metadata:
                  name: {{hub $role.metadata.name hub}}
                  labels:
                    rbac.open-cluster-management.io/filter: vm-clusterroles
                    clusterview.open-cluster-management.io/discoverable: "true"
                    rbac.open-cluster-management.io/custom-role: "true"
                rules: {{hub $role.rules | toRawJson | toLiteral hub}}
            {{hub- end hub}}
----

.. Apply the policy to your hub cluster by running the following command:

+
[source,bash]
----
oc apply -f policy-custom-vm-roles.yaml
----

.. Create a `PlacementBinding` to bind the policy to a `Placement` that targets your managed clusters. Create a YAML file that is named `placement-binding.yaml` with the following content:
+
[source,yaml]
----
apiVersion: policy.open-cluster-management.io/v1
kind: PlacementBinding
metadata: 
  name: binding-custom-vm-roles 
  namespace: open-cluster-management-global-set
placementRef: 
  apiGroup: cluster.open-cluster-management.io 
  kind: Placement 
  name: global
subjects: 
  - apiGroup: policy.open-cluster-management.io 
    kind: Policy
    name: policy-custom-vm-roles
----

.. Apply the placement binding by running the following command:

+
[source,bash]
----
oc apply -f placement-binding.yaml
----

.. Verify that the policy is compliant on all target clusters by running the following command. The output must show `Compliant` in the compliance state column for all clusters:

+
[source,bash]
----
oc get policy policy-custom-vm-roles -n open-cluster-management-global-set
----

. After you create a custom role and propagate it to managed clusters, reference that role in a `MulticlusterRoleAssignment` resource. You can create role assignments by using the console or the command-line interface:

* *Console reference:* Follow the steps to create a role assignment for built-in roles in the console at xref:../secure_clusters/fine_grain_ui_roles.adoc#fine-grain-ui-roles[Creating role assignments by using roles in the console]. 

* *Command-line reference:* Apply a `MulticlusterRoleAssignment` resource that references the custom role. See the following example that grants the `kvm-console-only` role to the `jane.developer` user on clusters that are selected by a the `global` placement:

+
[source,yaml]
----
apiVersion: rbac.open-cluster-management.io/v1beta1
kind: MulticlusterRoleAssignment
metadata: 
  name: custom-console-access 
  namespace: open-cluster-management-global-set
spec: 
  subject: 
    kind: User 
    name: jane.developer 
  roleAssignments: 
    - name: console-access 
      clusterRole: kvm-console-only 
      clusterSelection: 
        type: placements 
        placements: 
          - name: <your-placement>
            namespace: open-cluster-management-global-set
----

*Notes:* 

The `clusterSelection` field uses a `Placement` resource to determine to which managed clusters the role assignment applies. For more information, see xref:../secure_clusters/fine_grain_mca.adoc#fine-grain-mca[Fine-grained role-based access control _MulticlusterRoleAssignment_].
