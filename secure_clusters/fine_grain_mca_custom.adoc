= Using custom roles with MulticlusterRoleAssignment

In addition to the built-in roles provided in fine-grained role-based access control (RBAC) roles for virtualization, you can create custom `ClusterRole` resources to define permissions that are tailored to your environment. Custom roles are useful when the built-in roles do not match your access requirements, such as granting console-only access to virtual machines without lifecycle control.

You must ensure that the custom role exists on each managed cluster before the assignment takes effect. You can create a custom `ClusterRole`, distribute it by using a governance policy, and assign it through `MultiClusterRoleAssignments`.

*Required access:* Cluster administrator

== Prerequisites

* Enable fine-grained role-based access control. See _Enabling fine-grained role-based access control for virtualization_ for the procedure.
* Ensure that the governance policy framework is enabled on your hub cluster.
* Ensure you have a `Placement` resource that targets the desired managed clusters.

== Creating a custom role

Create a custom `ClusterRole` on the hub cluster with the required labels. Custom roles must include specific labels to integrate with the Red Hat Advanced Cluster Management console and `MulticlusterRoleAssignment`.

The following table describes the required labels for custom roles:

.Required labels for custom roles
[cols="1,1", options="header"]
|===
| Label | Value
| `rbac.open-cluster-management.io/filter` | `vm-clusterroles`
| `clusterview.open-cluster-management.io/discoverable` | `"true"`
| `rbac.open-cluster-management.io/custom-role` | `"true"`
|===

Complete the following steps to create a custom role:

. Create a YAML file that defines your custom `ClusterRole`. The following example creates a role named `kvm-console-only` that grants read-only access to virtual machines and the VNC console:
+
[source,yaml]
----
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata: 
  name: kvm-console-only 
  labels: 
    rbac.open-cluster-management.io/filter: vm-clusterroles 
    clusterview.open-cluster-management.io/discoverable: "true" 
    rbac.open-cluster-management.io/custom-role: "true"
rules: 
  - apiGroups: ["kubevirt.io"] 
    resources: ["virtualmachines", "virtualmachineinstances"] 
    verbs: ["get", "list", "watch"] 
  - apiGroups: ["subresources.kubevirt.io"] 
    resources: 
      - virtualmachineinstances/vnc 
    verbs: ["get"]
----

. Apply the resource on the hub cluster by running the following command:
+
[source,bash]
----
oc apply -f <your-custom-clusterrole>.yaml
----

== Propagating custom roles to managed clusters

Use a policy to automatically propagate custom roles from the hub cluster to all managed clusters. The policy discovers any `ClusterRole` with the `rbac.open-cluster-management.io/custom-role: "true"` label on the hub cluster and enforces the existence of those roles on the managed clusters.

Complete the following steps to create the propagation policy:

. Create a `ServiceAccount` with permission to list cluster-scoped resources on the hub cluster. The policy uses this service account to discover custom roles. Create a YAML file with the following content and apply it:
+
[source,yaml]
----
apiVersion: v1
kind: ServiceAccount
metadata: 
  name: policy-hub-clusterroles 
  namespace: open-cluster-management-global-set
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata: 
  name: open-cluster-management:policy-hub-clusterroles
rules: 
  - apiGroups: ["rbac.authorization.k8s.io"] 
    resources: ["clusterroles", "roles"] 
    verbs: ["list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata: 
  name: policy-hub-clusterroles-binding
roleRef: 
  apiGroup: rbac.authorization.k8s.io 
  kind: ClusterRole 
  name: open-cluster-management:policy-hub-clusterroles
subjects: 
  - kind: ServiceAccount 
    name: policy-hub-clusterroles 
    namespace: open-cluster-management-global-set
----

. Create the `Policy` resource YAML file and apply it to the hub cluster:
+
[source,yaml]
----
apiVersion: policy.open-cluster-management.io/v1
kind: Policy
metadata:
  name: policy-custom-vm-roles
  namespace: open-cluster-management-global-set
spec:
  disabled: false
  remediationAction: enforce
  hubTemplateOptions:
    serviceAccountName: policy-hub-clusterroles
  policy-templates:
    - objectDefinition:
        apiVersion: policy.open-cluster-management.io/v1
        kind: ConfigurationPolicy
        metadata:
          name: custom-vm-roles
        spec:
          remediationAction: enforce
          severity: medium
          object-templates-raw: |
            {{hub- range $role := (lookup "rbac.authorization.k8s.io/v1" "ClusterRole" "" "" "rbac.open-cluster-management.io/custom-role=true").items hub}}
            - complianceType: musthave
              objectDefinition:
                apiVersion: rbac.authorization.k8s.io/v1
                kind: ClusterRole
                metadata:
                  name: {{hub $role.metadata.name hub}}
                  labels:
                    rbac.open-cluster-management.io/filter: vm-clusterroles
                    clusterview.open-cluster-management.io/discoverable: "true"
                    rbac.open-cluster-management.io/custom-role: "true"
                rules: {{hub $role.rules | toRawJson | toLiteral hub}}
            {{hub- end hub}}
----

. Create a `PlacementBinding` to bind the policy to a `Placement` that targets your managed clusters. Create a YAML file with the following content and apply it:
+
[source,yaml]
----
apiVersion: policy.open-cluster-management.io/v1
kind: PlacementBinding
metadata: 
  name: binding-custom-vm-roles 
  namespace: open-cluster-management-global-set
placementRef: 
  apiGroup: cluster.open-cluster-management.io 
  kind: Placement 
  name: global
subjects: 
  - apiGroup: policy.open-cluster-management.io 
    kind: Policy
    name: policy-custom-vm-roles
----

. Verify that the policy is compliant on all target clusters by running the following command:
+
[source,bash]
----
oc get policy policy-custom-vm-roles -n open-cluster-management-global-set
----
+
The output must show `Compliant` in the compliance state column for all clusters.

== Referencing a custom role in a MulticlusterRoleAssignment

After you create a custom role and propagate it to managed clusters, reference it in a `MulticlusterRoleAssignment` resource. You can create role assignments by using the console or the command-line interface (CLI):

* *Console:* Follow the same steps as you would when creating a role assignment for built-in roles. For the full procedure, see xref:../secure_clusters/index.adoc#fine-grain-ui-roles[Creating role assignments by using roles in the console].

* *CLI:* Apply a `MulticlusterRoleAssignment` resource that references the custom role:
+
[source,yaml]
----
apiVersion: rbac.open-cluster-management.io/v1beta1
kind: MulticlusterRoleAssignment
metadata: 
  name: custom-console-access 
  namespace: open-cluster-management-global-set
spec: 
  subject: 
    kind: User 
    name: jane.developer 
  roleAssignments: 
    - name: console-access 
      clusterRole: kvm-console-only 
      clusterSelection: 
        type: placements 
        placements: 
          - name: <your-placement>
            namespace: open-cluster-management-global-set
----

[NOTE]
====
The `clusterSelection` field uses a `Placement` resource to determine which managed clusters the role assignment applies to. For more information, see xref:../secure_clusters/index.adoc#mra-placement[Creating and using placements].
====

[NOTE]
====
The hub user must have the `acm-vm-fleet:view` `ClusterRole` bound on the hub cluster. Create a `ClusterRoleBinding` on the hub cluster to grant this role before proceeding. For more information, see xref:../secure_clusters/index.adoc#fine-grain-roles-descriptions[Fine-grained RBAC roles and descriptions].
====
