[#whats-new-acm]
= What's new for {acm-short}

{acm} provides visibility of your entire Kubernetes domain with built-in governance, cluster lifecycle management, and application lifecycle management, along with observability. 

*Important:* {acm-short} supports all providers that are certified through the Cloud Native Computing Foundation (CNCF) Kubernetes Conformance Program. Choose a vendor that is recognized by CNFC for your hybrid cloud multicluster management.

See the following information about using CNFC providers:

* Learn how CNFC providers are certified at link:https://www.cncf.io/training/certification/software-conformance/[Certified Kubernetes Conformance]. 

* For Red Hat support information about CNFC third-party providers, see link:https://access.redhat.com/third-party-software-support[Red Hat support with third party components], or link:https://access.redhat.com/support/contact/[Contact Red Hat support].

* If you bring your own CNFC conformance certified cluster, you need to change the {ocp-short} CLI `oc` command to the Kubernetes CLI command, `kubectl`.

[#install-acm-whats-new]
== Installation

As part of {acm-short} advanced configuration, the `edge-manager-preview` component is now deployed through the `multiclusterhub-operator` during installation. By default, the `edge-manager-preview` component is disabled and can be enabled from the `MultiClusterHub` custom resource that is deployed on your hub cluster. Learn about {acm-short} advanced configuration options at link:../install/adv_config_install.adoc#advanced-config-hub[MultiClusterHub advanced configuration] in the documentation.

[#governance-whats-new]
== Governance

* The Operator policy includes more in its `status.conditions`, so now you can view the `NoDeprecations` condition. See the link:../governance/operator_pol_ctrl.adoc#operator-policy-yaml-table[Operator policy YAML table].

* You can now view Kyverno policies and audit results in the *Discovered policies* table from the console.

* You can now use templates in the `spec.versions` parameter of the Operator policy controller to list the installed `ClusterServiceVersion` names that are compliant. See the link:../governance/operator_pol_ctrl.adoc#operator-policy-yaml-table[Operator policy YAML table].

* You can now filter and enforce an unnamed `objectDefinition` in a `ConfigurationPolicy` resource by providing a label selector in the `objectSelector` parameter to select the objects that you want to apply to the policy. For more information, see link:../governance/adv_template_process.adoc#object-selector[Configuration policy object selector].

* For managed clusters in `ConfigurationPolicy`, you now have two new variables: `.ObjectName` and `.ObjectNamespace`. Use templating to support these new variables. For more information, see the link:../governance/template_support_intro.adoc#template-comparison-table[Comparison of hub cluster and managed cluster templates].

See link:../governance/grc_intro.adoc#governance[Governance] to learn more about the dashboard and the policy framework.

[#dr4hub-whats-new]
== Backup and restore

* You now can use the {acm-short} backup and restore component to install {acm-short} policies that can be used to backup and restore the {ocp-virt-short} resources. For more information, see link:../business_continuity//backup_restore/backup_configure_virtualization.adoc#configure-virtualization[Configuring backup and restore for {ocp-virt} using {acm} policies]

* When you install VolSync from {acm-short} on your managed cluster, VolSync is now installed in the `volsync-system` namespace on your managed cluster.

* You can now deploy VolSync from {acm-short} onto non-{ocp-short} managed clusters.

* To learn about disaster recovery solutions for your hub cluster, see link:../business_continuity/backup_restore/backup_install.adoc#backup-intro[Backup and restore].
