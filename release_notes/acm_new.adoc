[#new-features-acm]
= New features and enhancements for {acm-short}

{acm} 2.16 provides visibility of your entire Kubernetes domain with built-in governance, cluster lifecycle management, and application lifecycle management with GitOps, along with observability. 

{acm-short} version 2.16 is released with the {mce-short} version 2.11 for Cluster lifecycle management. To learn about cluster management this release, see the link:../clusters/release_notes/mce_release_notes.adoc#mce-release-notes[Release notes for Cluster lifecycle with {mce-short}].

Access the link:https://access.redhat.com/articles/7133095[{acm-short} Support Matrix] to learn about hub cluster and managed cluster requirements and support for each component. For lifecycle information, see link:https://access.redhat.com/support/policy/updates/openshift[{ocp} Life Cycle policy].

*Important:*

- {acm-short} supports all providers that are certified through the Cloud Native Computing Foundation (CNCF) Kubernetes Conformance Program. Choose a vendor that is recognized by CNCF for your hybrid cloud multicluster management. See the following information about using CNCF providers:

- Learn how CNCF providers are certified at link:https://www.cncf.io/training/certification/software-conformance/[Certified Kubernetes Conformance]. 

- For Red Hat support information about CNCF third-party providers, see link:https://access.redhat.com/articles/third-party-software-support[Red Hat support with third party components], or link:https://access.redhat.com/support/contact/[Contact Red Hat support].

- If you bring your own CNCF conformance certified cluster, you need to change the {ocp-short} CLI `oc` command to the Kubernetes CLI command, `kubectl`. 

[#general-announcement]
== General announcements for this release

{acm-short} is available on the link:https://aws.amazon.com/marketplace/pp/prodview-s2nb6rqz2i3ru[AWS Marketplace] with either on-demand or annual pricing and a simplified billing option for running {acm-short} on {rosa} clusters. {acm-short} on the AWS Marketplace offers billing consistency, flexible resource consumption, and cost efficiency. 

- Purchase from the AWS Marketplace, then you can install `MultiClusterHub` resources and manage your clusters. To view the overall consumption, go to link:https://console.redhat.com/subscriptions/usage/openshift[console.redhat.com]. Click *Subscriptions Usage* > *OpenShift*. Select *Variant: Red Hat Advanced Cluster Management* from the drop-down menu.

- Use the _Attach_ feature with Red Hat OpenShift Lightspeed, a generative AI-powered virtual assistant for {ocp}, to add managed cluster resource details as context for questions. See the link:https://docs.redhat.com/en/documentation/red_hat_openshift_lightspeed/1.0/html/install/index[Red Hat OpenShift Lightspeed] installation documentation to learn how to install Lightspeed. After installing, click *Infrastructure* > *Clusters* > *Cluster details* on any managed cluster page to access the assistant. The _Attach_ feature automatically adds the relevant cluster YAML file details from the `ManagedCluster` and `ManagedClusterInfo` resource to the agent conversation.

[#observability-new-features]
== Observability

Learn about new features for Observability.

- The `RightSizingRecommendation` feature to optimize workloads is now generally available. After you enable the observability service, namespace right-sizing and virtualization right-sizing are enabled by default. To learn more, see link:../observability/obs_right_size_intro.adoc#right-size-intro[`RightSizingRecommendation` guides].

- You can now configure resource requirements for observability using the `AddonDeploymentConfig` resource when observability is enabled through the multicluster observability add-on. For more information, see link:../observability/obs_enable_mcoa.adoc#enable-mcoa[Enabling the multicluster observability add-on] and link:../add-ons/configure_klusterlet_addons.adoc#setting-addondeploymentconfig-klusterlet-addons[Setting up the AddOnDeploymentConfig to configure klusterlet add-ons].

- The maximum compaction level for the Thanos compactor is `4`. This configuration enables the creation of one-hour downsampled blocks. As a result, memory usage for the `observability-thanos-compact-0` pod and storage consumption in the object storage bucket increase.  The Thanos compactor completes more `PUT` and `DELETE` operations to create blocks with a larger duration. See, link:../observability/observability_arch.adoc#observability-arch[Observability architecture].

See link:../observability/observe_environments_intro.adoc#observing-environments-intro[Observability service] to learn more.

[#virt-new-features]
== Virtualization

* Fine-grained role-based access control (RBAC) for virtualization is now generally available. Fine-grained RBAC provides administrators with the precision to manage permissions across managed clusters with greater security and flexibility.
+
* The {acm-short} fleet management interface now includes specialized roles designed specifically for managing virtual machines across clusters, which extend standard virtualization capabilities, offering specific access levels for fleet-wide operations.
+
* With the new `MultiClusterRoleAssignment` custom resource, you can manage role-based access control (RBAC) for virtual machines. As an administer, use the declarative method to centralize permission logic on the hub cluster for propagation with managed clusters. See link:../secure_clusters/fine_grain_mca.adoc#fine-grain-mca[Fine-grained role-based access control _MulticlusterRoleAssignment_] to learn more. See examples in xref:../secure_clusters/fine_grain_mca_examples.adoc#fine-grain-mca-examples[_MulticlusterRoleAssignment_ examples for fine-grained role-based access control].

* You can now edit the `HyperConverged` resource to improve flexibility when your infrastructure requirements change and fine-tune your deployment. See link:../virtualization/migrate_vm.adoc#migrate-vm[Migrating virtual machines between clusters] to learn more.

See link:../virtualization/virtualization_intro.adoc[Virtualization].
