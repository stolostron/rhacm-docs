[#new-features-acm]
= New features and enhancements for {acm-short}

[role="_abstract"]
{acm} 5.0 provides visibility of your entire Kubernetes domain with built-in governance, cluster lifecycle management, and application lifecycle management with GitOps, along with observability.

{acm-short} version 5.0 is released with the {mce-short} version 5.0 for Cluster lifecycle management. To learn about cluster management this release, see the link:../mce_release_notes/mce_release_notes_intro.adoc#mce-release-notes-intro[Release notes for the {mce-short}].

Access the link:https://access.redhat.com/articles/7149098[{acm-short} Support Matrix] to learn about hub cluster and managed cluster requirements and support for each component. For lifecycle information, see link:https://access.redhat.com/support/policy/updates/openshift[{ocp} Life Cycle policy].

== New features and enhancements for each component

Learn specific details about new features for components within {acm-short}:

== Installation

Learn about {acm-short} installation features and enhancements.

* The {mce-short} subscription now automatically inherits the approval setting from the `MultiClusterHub` subscription. This allows you to configure {mce-short} subscription approval to manual or automatic. The manual approval setting can be configured if you do not want clusters to be automatically upgraded. 

* The {mce-short} discovery includes additional metadata fields to contain information from {ocm} subscriptions. This metadata provides more granular control over the discovery process by improving cluster classification, support tier visibility, and environment distinction without requiring additional API calls. Additionally, the `DiscoveredCluster` resource contains a status field that tracks the import time and the name of the related `ManagedCluster` resource.

* The new installation channel, `stable-5.0`, is available in this release of {acm-short}. The `release-5.0` channel continues to be supported in addition for legacy compatibility.

* Network policy support is enhanced for the {mce-short} in order to deploy network policies associated with {acm-short} components.

* The Maestro component is deprecated and disabled in the {mce-short}. 


[#console-new-features]
== Console

Learn about what is new in the {acm-short} integrated console, which includes search capability.

* When deleting a managed cluster, you can now preserve the underlying cluster infrastructure by selecting the *Preserve cluster infrastructure* option in the {acm-short} console. This new option in the user interface sets the `preserveOnDelete` field without requiring command line access.

* You can now preserve resources on deletion when configuring the sync policy in the console for `ApplicationSet` resources. Setting the `preserveResourcesOnDeletion` safety flag prevents accidental deletion of child `Application` resources when an `ApplicationSet` is removed or when placement changes cause applications to be pruned from spoke clusters.

* The console now displays more specific `NodePool` health status updates for hosted clusters. The updated status messages include error and warning states to help operators identify issues directly from the {acm-short} console.

* The console welcome page contains a new card describing search capabilities and a link to the external _Open Cluster Management_ project, on the technical community card.

* References to _Red Hat Insights_ are rebranded to _Red Hat Lightspeed_ in the {acm-short} console to align with updated branding across Red Hat. Updated references include user interface labels, external links, and localized text across all supported locales.


[#clusters-new-features]
== Clusters

Learn about new features for managed clusters in {acm-short}.

* You can now add rich-text descriptions to the cluster details page to help with managing large fleets. Use the _Description_ field to annotate clusters with Markdown-formatted text and clickable links to per-cluster tools, such as monitoring dashboards, logging endpoints, and runbooks, which are displayed on the cluster overview page.

* You can navigate more easily between clusters with usability improvements on the hub cluster and managed cluster consoles. The managed cluster list contains a link to each managed cluster console, and the console for each managed cluster contains a link to the hub cluster.


[#applications-new-features]
== Applications and GitOps

Learn about new features for application management and GitOps.

* The `ManagedCluster` registry is integrated with the {acm-short} GitOps add-on. You can now use the `ManagedClusterImageRegistry` resource to configure image mirroring when using the {gitops} add-on for disconnected clusters from other Kubernetes providers.


== Observability

Learn about new features for observability.

* You can now configure the multicluster observability add-on to automatically discover user-defined `ScrapeConfig`, `PrometheusRule`, and `PrometheusAgent` configurations and attach them to target placements without manually patching the `ClusterManagementAddOn` resource.

* The multicluster observability add-on now supports automatic alert forwarding from managed clusters to the Alertmanager on the hub cluster.

* The multicluster observability add-on now deploys dependent custom resource definitions from the endpoint monitoring operator on managed clusters, which reduces the impact on `etcd` resources on the hub cluster. This improvement is more significant in deployments with many managed clusters.

* Perses dashboards are now generally available and fully supported. You can enable Perses dashboards to view hub cluster and managed cluster metrics from the OpenShift Container Platform console, and build real-time views of metrics, traces, logs, and profiling data from a single interface. 

* Alerts sent from managed clusters are now routed through the Observatorium API on the hub cluster, which fans out each request to all Alertmanager replicas. This ensures consistent state across all Alertmanager replicas to avoid sending duplicate alerts.

* *Technology Preview:* You can now collect high-resolution metrics from managed clusters to the hub cluster more frequently than 90 seconds by configuring raw resolution on `ScrapeConfig` resources when using the multicluster observability add-on. 


[#governance-new-features]
== Governance

Learn about new features for Governance.

* The Governance and Search components in {acm-short} now use the specialized policy types used by Kyverno to ensure accurate compliance reporting and resource discovery across managed clusters, and improve performance. In Kyverno, `ClusterPolicy` is superseded by Common Expression Language (CEL) based policy types, including `ValidatingPolicy`, `MutatingPolicy`, `GeneratingPolicy`, `CleanupPolicy`, and `ImageValidatingPolicy`, which are available in this release of {acm-short}. 


[#support-new-features]
== Support

Learn about new features that assist in getting support.

* Must-gather reports now include component version information. This helps support teams and administrators to more easily identify installation-related issues without reviewing version details from individual deployment resources.
