[#upgrade-stuck]
== Upgrading an existing {acm-short} cluster with {ocp-short} 4.18 causes the upgrade to get stuck in `upgrading` status while installing the CRD 
//2.13:19151

When you upgrade to {acm-short} 2.13 with an {ocp-short} version 4.18 cluster, you receive an error installing the CRD and remain in a `stuck` status. 

To resolve this issue, upgrade directly to {acm-short} 2.13.2, even if you upgraded to 2.13.1 and receive this error. Complete the following steps:

. To get more information about the error, run the following command:

+
[source,bash]
----
oc get multiclusterhubs -n open-cluster-management -o yaml
----
+
You might receive the following error message about a failed installation of `multiclusterobservabilities.observability.open-cluster-management.io` on your hub cluster:

+
[source,bash]
----
message: 'Error installing CRDs: CustomResourceDefinition.apiextensions.k8s.io
"multiclusterobservabilities.observability.open-cluster-management.io" is 
invalid: spec.conversion.webhookClientConfig.caBundle: Invalid value: []byte{0x5c,0x6e}: unable to load root certificates: unable to parse bytes as PEM block'
 reason: FailedDeployingComponent
 status: "False"
 type: Progressing
desiredVersion: 2.13.0
phase: Installing
----

. Run the following command to check the progress of the {acm-short} upgrade:

+
[source,bash]
----
oc get multiclusterhubs -n open-cluster-management -o yaml
----
+
The output states that hub cluster components are ready, as in the following example:

+
[source,bash]
----
message: 'created new resource: CustomResourceDefinition multiclusterobservabilities.observability.open-cluster-management.io'
 reason: NewResourceCreated
 status: "True"
 type: Progressing
 message: All hub components ready.
 ...
 reason: ComponentsAvailable
 status: "True"
 type: Complete
----

[#upgrade-fail-unknown]
== Local-cluster status unknown after upgrade to version 2.13
//2.13:19368

After you upgrade to {acm-short} 2.13, your `local-cluster` status might change to `Unknown`. The `ManagedCluster` resource has a `ClusterCertificateRotated` condition with a `False` status, and the following message: `Stop creating CSR since there are too many CSRs created already on the hub.`

. Check the number of `CertificateSigningRequests` (CSRs). Run the following command on the hub cluster:

+
[source,bash]
----
oc get csr -l 'open-cluster-management.io/cluster-name=local-cluster,!open-cluster-management.io/addon-name'
----
+
If the total number in the output is `10`, it reached the maximum CSR limit. The `local-cluster` status will recover automatically within 1-2 hours as CSRs are periodically purged. 

. Run the following command to manually delete the CRSs if you want to recover immediately:

+
[source,bash]
----
oc delete csr -l 'open-cluster-management.io/cluster-name=local-cluster,!open-cluster-management.io/addon-name'
----

[#uninstall-manual-remove-cr]
== Uninstalling and reinstalling earlier versions with an upgrade can fail
//2.10:10953 and 2:12:14343, to name a few issues for this

Uninstalling {acm-short} from {ocp-short} can cause issues if you later want to install earlier versions and then upgrade. For instance, when you uninstall {acm-short}, then install an earlier version of {acm-short} and upgrade that version, the upgrade might fail. The upgrade fails if the custom resources were not removed.

Follow the link:../install/cleanup_reinstall.adoc#cleanup-reinstall[Cleaning up artifacts before reinstalling] procedure to prevent this problem.

[#install-arm-diable]
== Infrastructure operator error with ARM converged flow
//2.9: 8558
 
When you install the `infrastructure-operator`, converged flow with ARM does not work. Set `ALLOW_CONVERGED_FLOW` to `false` to resolve this issue.

. Run the following command to create a `ConfigMap` resource:

+
----
oc create -f
----

. Apply your file by running `oc apply -f`. See the following file sample with `ALLOW_CONVERGED_FLOW` set to `false`:

+
[source,yaml]
----
apiVersion: v1
kind: ConfigMap
metadata:
  name: my-assisted-service-config
  namespace: assisted-installer
data:
  ALLOW_CONVERGED_FLOW: false
----

. Annotate the `agentserviceconfig` with the following command:

+
----
oc annotate --overwrite AgentServiceConfig agent unsupported.agent-install.openshift.io/assisted-service-configmap=my-assisted-service-config
----

The agent appears in the inventory when the issue is resolved.
