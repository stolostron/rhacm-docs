[#alert-forward-fails]
= Manually configured alert forwarding fails

[role="_abstract"]
When you update to {acm-short} {product-version-prev} and later, alert forwarding fails if you disabled automatic configuration by setting `mco-disable-alerting: true` in the `MultiClusterObservability` custom resource, and if you manually configured alert forwarding.

Alert forwarding fails after you update because the name of the `observability-alertmanager-accessor` and `hub-alertmanager-router-ca` secrets were changed to include a postfix of the hub cluster ID.

The hub cluster ID is obtained from the `uuid` field in the metadata of the `ClusterVersion` custom resource on the hub cluster. The ID, with dashes removed and trimmed to the first 19 characters, is appended to the `alertmanager` secrets.

.Procedure

. Update your alert forwarding configuration that you manually configured to use the new names of the secrets.
. Update the secret name in the `cluster-monitoring-config` config map in the `openshift-monitoring` namespace for platform alerts. Update the secret name in the `user-workload-monitoring-config` config map in the `openshift-user-workload-monitoring` namespace for user workload alerts. Find the new secret names in the `openshift-monitoring` and `openshift-user-workload-monitoring` namespaces.
