[#subscribing-git-resources]
= Subscribe to Git resources

[role="_abstract"]
By default, when a subscription deploys subscribed applications to target clusters, the applications are deployed to that subscription namespace, even if the application resources are associated with other namespaces. A _subscription administrator_ can change default behavior, as described in xref:../applications/subscription_admin.adoc#granting-subscription-admin-privilege[Grant subscription admin privilege].

*Deprecation:* Application _subscription_, and all processes that use Application subscription, is deprecated. See link:../gitops/gitops_overview.adoc#gitops-overview[GitOps overview] for updated function.

Additionally, if an application resource exists in the cluster and was not created by the subscription, the subscription cannot apply a new resource on that existing resource. See the following processes to change default settings as the subscription administrator:

*Required access:* Cluster administrator

* xref:../applications/subscribe_git_create.adoc#creating-application-resources-git[Create application resources in Git]
* xref:../applications/subscribe_git_elements.adoc#subscribing-specific-git[Subscribe to specific Git elements]
* xref:../applications/subscribe_git_namespace.adoc#namespace-example[Application namespace example]
* xref:../applications/subscribe_git_overwrite.adoc#resource-overwrite-example[Resource overwrite example]
