[#ansible_config]
= Configure {aap-short}

[role="_abstract"]
With {aap-short} jobs, you can automate tasks and integrate with external services, such as Slack and PagerDuty services. Your Git repository resource root path will contain `prehook` and `posthook` directories for {aap-short} jobs that run as part of deploying the application, updating the application, or removing the application from a cluster.

*Required access:* Cluster administrator

*Deprecation:* Application _subscription_, and all processes that use Application subscription, is deprecated. See link:../gitops/gitops_overview.adoc#gitops-overview[GitOps overview] for updated function.

Complete the following steps to configure {aap-short} with Git subscriptions:

.Procedure

. Create an {aap-short} secret in the subscription namespace so that prehook and posthook jobs can authenticate to {aap-short}. See xref:../applications/ansible_secrets.adoc#ansible-secrets[Set up {aap-short} secrets].
. Set secret reconciliation so the main subscription refreshes after prehook and posthook `AnsibleJob` resources, or the main subscription, change in Git. See xref:../applications/ansible_secret_reconciliation.adoc#ansible-secret-reconciliation[Set secret reconciliation].
. See the sample `AnsibleJob` YAML to define jobs in the Git `prehook` and `posthook` folders. See xref:../applications/ansible_sample_yaml.adoc#ansible-sample-yaml[Use {aap-short} sample YAML files].
. Launch an {aap-short} Workflow when you need to run a workflow template instead of a single job template. See xref:../applications/ansible_launch_workflow.adoc#launch-workflow[Launch Workflow].
. See the workflow sample YAML to specify `workflow_template_name` in your `AnsibleJob` resource. See xref:../applications/ansible_workflow_sample.adoc#workflow-sample-yaml[Use {aap-short} sample YAML Workflow].
