= Managing fine-grained role-based access control

{acm} supports fine-grained role-based access control (RBAC). As a cluster administrator, you can manage and control permissions at the namespace level on managed clusters rather than at the cluster level. Grant permissions to a namespace without granting permission to the entire managed cluster, or virtual machine. 

*Required access:* Cluster administrator

*Note:* Action buttons are disabled from the console if the user-role access is impermissible.

If you installed operators that create cluster roles, you do not need to create them. You can create `clusterroles` manually if you need to create them.

To learn about {ocp-short} default and virtualization roles and permissions, see link:https://docs.redhat.com/en/documentation/openshift_container_platform/4.17/html/virtualization/about#authorization_virt-security-policies[Authorization] in the {ocp-short} documentation.

See xref:../secure_cluster/rbac_implement_rhacm.adoc#rhacm-rbac-implement[Implementing role-based access control] for more details about {acm-short} role-based access.

You can grant access to the following roles for {ocp-virt-short}, which are extensions of the default roles:

- `kubevirt.io:view`: only view resources
- `kubevirt.io:edit`: modify resources
- `kubevirt.io:admin`: view, modify, delete resources; grant permissions

To use fine-grained role-based access control, see the following procedure:

. In your `MultiClusterHub` custom resource `spec.overrides.components` field, set `fine-grained-rbac-preview` to `true` to enable the feature.
. In your `MultiClusterHub` custom resource `spec.overrides.components` field, set `search` to `enabled` to retrieve a list of managed clusters namespaces that can represent virtual machines that are used for access control.
. On the hub cluster, label `clusterroles` with the `rbac.open-cluster-management.io/filter=vm-clusterroles` filter so you see cluster roles in the console when you create or edit cluster permissions.
. Ensure you have virtual machines by creating or migrating them on the hub cluster, which gives the managed cluster namespaces.
. Verify that the `ClusterPermission` resource is created and is in ready status.
