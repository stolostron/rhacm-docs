= Deploying Submariner manually

[role="_abstract"]
If your cluster is hosted on a provider that does not support automatic Submariner deployment, see the following sections to prepare the infrastructure manually. Each provider has unique steps for preparation, so make sure to select the correct provider.

*Note:* By default, Submariner uses IP security (IPsec) to establish secure tunnels between the clusters on the gateway nodes. You can either use the default IPsec NATT port, or you can xref:../submariner/subm_customize.adoc#customizing-submariner[specify a different port] that you configure. When you prepare or deploy clusters without specifying an IPsec NATT port, 4500/UDP is used for the connections. See _Customizing Submariner deployments_ in the additional resources section to learn more.

* Before you deploy Submariner with {acm}, you must prepare the clusters on the hosting environment for the connection. See xref:../submariner/deploy_subm_console.adoc#deploying-submariner-console[Deploying Submariner by using the console] to learn how to automatically deploy Submariner on supported clusters by using the console.
* If you are using VMware vSphere or bare metal with hosted control planes, Submariner automatically labels one or more existing worker nodes as gateways during installation. If you want to specify certain nodes as gateways, apply the `submariner.io/gateway=true` label to your nodes.
