= Creating a policy violation automation from the console

[role="_abstract"]
Configure a policy violation automation from the {acm-short} console to begin automation tasks when a policy becomes non-compliant. 

The automation displays in the _Automation_ column. 
*Required access:* Cluster administrator

.Prerequisites

* Access to the {acm-short} console.
* An active {aap} credential configured in {acm-short}.

.Procedure

. Log in to your {acm-short} hub cluster.
. From the navigation menu, select *Governance* and click the _Policies_ tab.
. Find the target policy in the table and click *Configure* in the _Automation_ column.

. In the _Ansible credential_ section, select your {aap-short} credential from the list.

+
*Note:* This credential is copied to the same namespace as the policy. The generated `AnsibleJob` resource uses the {aap-short} credential to run the automation. Changes to the {aap-short} credential update automatically.

. Select an {aap-short} job template.

. In the _Extra variables_ section, define parameter values in the `extra_vars` section of the `PolicyAutomation`.

. Select the automation frequency:
* Run once mode
* Run everyEvent mode
* Disable automation

. Save your policy violation automation by selecting *Submit*. Clicking the *View Job* link from the Ansible job details side panel, naviagates to the job template on the _Search_ page. 

+
*Note:* When you delete a policy that has an associated policy automation, the policy automation is automatically deleted as part of clean up.
