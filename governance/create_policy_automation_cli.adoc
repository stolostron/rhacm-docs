= Creating a policy violation automation from the command-line interface

[role="_abstract"]
Configure a policy violation automation from the command-line interface by defining and applying a `PolicyAutomation` custom resource.

.Prerequisites

* {ocp} command-line interface installed and authenticated to the hub cluster.
* A target policy deployed on the hub cluster.

.Procedure

. Log in to your hub cluster. Run the following command:

+
[source,bash]
----
oc login <hub_cluster_url>
----

. Find the name and namespace of the policy that you want to automate.

. Create a `PolicyAutomation` resource. Your YAML file might resemble the following  example:

+
[source,yaml]
----
apiVersion: policy.open-cluster-management.io/v1beta1
kind: PolicyAutomation
metadata:
  name: policyname-policy-automation
spec:
  automationDef:
    extra_vars:
      your_var: your_value
    name: Policy Compliance Template
    secret: ansible-tower
    type: AnsibleJob
  mode: disabled
  policyRef: policyname
----

. Update the following fields within your resource definition:

+
* `spec.automationDef.name`: Match your exact {aap} job template name.
* `spec.automationDef.extra_vars`: Add parameters passed directly to the automation template.
* `spec.mode`: Set to `once`, `everyEvent`, or `disabled`.
* `spec.policyRef`: Reference the exact target policy name.

. Create an {aap-short} credential secret containing the Ansible Tower token in the same namespace as the `PolicyAutomation` resource. 

. Apply the configuration file the cluster. Run the following command:

+
[source,bash]
----
oc apply -f <filename>.yaml
----

. To configure an immediate run of the policy automation, add the following annotation to the `PolicyAutomation` resource:

+
[source,yaml]
----
metadata:
  annotations:
    policy.open-cluster-management.io/rerun: "true"
----
