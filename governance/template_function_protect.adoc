[#protect]
= protect

[role="_abstract"]
The `protect` function enables you to encrypt a string in a hub cluster policy template. It is automatically decrypted on the managed cluster when the policy is evaluated. Use this function to encrypt sensitive hub cluster template values in transit to managed clusters.

View the following example of the configuration policy that uses the `protect` function:

[source,yaml]
----
apiVersion: policy.open-cluster-management.io/v1
kind: ConfigurationPolicy
metadata:
  name: demo-template-function
spec:
  object-templates:
  - objectDefinition:
    ...
    spec:
      enabled: >-
        {{hub (lookup "v1" "Secret" "default" "my-hub-secret").data.message | protect hub}}
----
+
* In this example, a _lookup_ hub cluster template encrypts the secret value. On the replicated policy, the value resembles `$ocm_encrypted:okrrBqt72oI+3WT/0vxeI3vGa+wpLD7Z0ZxFMLvL204=`.
* Encryption uses AES-CBC with 256-bit keys.
* Each managed cluster has a unique key, rotated every 30 days.
* The decrypted value is never stored in the policy on the managed cluster.
* To force immediate key rotation, delete the `policy.open-cluster-management.io/last-rotated` annotation on the `policy-encryption-key` Secret in the managed cluster namespace on the hub cluster. Policies are then reprocessed to use the new encryption key.
