[#global-hub-upgrade-postgres]
= Recovering data from the upgraded built-in Postgres

Starting with {global-hub} version 1.4.0, the built-in Postgres database gets upgraded to version 16. This upgrade replaces the earlier `multicluster-global-hub-postgres` instance with the new `multicluster-global-hub-postgressql` instance. By default, this upgrade automatically re-syncs real-time data, such as: `policies` and `clusters`, to the new Postgres instance. However, historical data, such as: `event` and `history` tables, does not automatically get recovered. 

If you want to keep historical data, complete the following sections: 

* <<restoring-data, Restoring historical data>>
* <<deleting-legacy-postgres, Deleting legacy built-in postgres data>>

[#restoring-data]
== Restoring historical data

When your historical data gets removed by the {global-hub} upgrade to version 1.4.0, recover your data by completing the following steps:

. Close the {acm} Git repo to access the shell script that you need to recover your data by running the following command: 

+
[source,bash]
----
oc git clone https://github.com/stolostron/multicluster-global-hub.git
----

. Restore your history tables by running the following shell script: 

+
[source,bash]
----
oc ./doc/upgrade/restore_history_tables.sh
----

. Restore your event tables by running the following shell script: 

+
[source,bash]
----
oc ./doc/upgrade/restore_event_tables.sh
----

[#deleting-legacy-postgres]
== Deleting legacy built-in Postgres data

After {global-hub} upgrades to version 1.4.0, it switches to the new built-in Postgres instance. The global hub operator does not automatically delete resources associated with the legacy Postgres instance. To delete the legacy Postgres resources, run the following script: 


[source,bash]
----
oc ./doc/upgrade/cleanup_legacy_postgres.sh
----
