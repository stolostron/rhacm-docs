= Zero Touch Provisioning migration overview

Zero Touch Provisioning (ZTP) migration facilitates the transfer of fully provisioned, bare-metal clusters, such as Single Node OpenShift (SNO), from a source Red Hat Advanced Cluster Management (RHACM) hub cluster to a target hub cluster. This process maintains cluster state, configuration, and GitOps management throughout the transition.

The migration process automatically transfers several resource categories from the source hub to the target hub to ensure continuity.

* The following core resources are included in the migration:
+
ManagedCluster:: Facilitates cluster registration and management.
KlusterletAddonConfig:: Defines add-on configurations for managed clusters.

* The following deployment resources are included in the migration:
+
ClusterDeployment::
Contains Hive deployment configuration while preserving status.
ImageClusterInstall::
Manages image-based installation configuration while preserving status.

* The following secrets are included in the migration:
+
Admin credentials:: Includes `<Cluster Name>-admin-password` and `<Cluster Name>-admin-kubeconfig`.
Metadata and reconfiguration:: Includes `<Cluster Name>-metadata-json` and `<Cluster Name>-seed-reconfiguration`.
Network secrets:: Includes secrets with the `siteconfig.open-cluster-management.io/sync-wave` annotation.
Referenced secrets:: Automatically collects BMC credentials and pull secrets referenced in the `BareMetalHost` and `ClusterDeployment` specifications.

The following ConfigMaps are included in the migration:
+
Referenced ConfigMaps:: Automatically collects ConfigMaps that are referenced.
Extra Manifests:: ConfigMaps that are referenced in `ImageClusterInstall.spec.extraManifestsRefs`

The following Bare metal resources with status preserved are included in the migration:
+
BareMetalHost:: Physical server inventory and state
HostFirmwareSettings:: BIOS/firmware configurations
FirmwareSchema:: Firmware setting schemas
HostFirmwareComponents:: Individual firmware components

The following is excluded from migration:
+
ClusterInstance Resources:: Managed by GitOps (Argo CD). You must manually apply GitOps applications to the target hub after cluster migration.
Policy Resources:: Must be redeployed via GitOps applications on target hub
Application Resources:: GitOps applications managing cluster configuration
