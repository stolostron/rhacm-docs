= Zero Touch Provisioning migration overview

Zero Touch Provisioning (ZTP) migration facilitates the transfer of fully provisioned, bare-metal clusters, such as {sno}, from a source {acm-short} hub cluster to a target hub cluster. Migration maintains the cluster state, configuration, and GitOps management throughout the transition.
//is this GitOps in general or OCP GitOps?


The migration procedure automatically transfers several resource categories from the source hub cluster to the target hub cluster to ensure continuity with the following processes:

Pre-migration verification:: Verify the clusters on the source hub cluster to ensure they are ready for migration.
Apply policy applications:: Manually apply policy applications from the source hub cluster to the target hub cluster.
Create migration resource:: Manually create the migration resource on the global hub cluster to initiate the process.
Migration execution:: The global hub cluster automatically transfers resources and registers clusters to the target hub cluster.
Apply ClusterInstance applications:: Manually apply the ClusterInstance applications to the target hub cluster.
Verify migration:: On the target hub cluster, verify that all clusters are available, test cluster operations, and confirm policy compliance.
Cleanup source hub cluster:: Manually delete the GitOps applications and the ClusterInstance resources from the source hub cluster.

See the following table for the supported versions of {acm-short} and {ocp-short} for migration:

.Version Requirements for hub cluster components
|===
| Component | Source hub cluster | Target hub cluster| Notes

| {acm-short}
| Version `N`
| Version `N to N+1`, and EUS version support
| None

| {ocp-short}
| Version `4.x`
| Version `4.x`
| Should be compatible with {acm-short} version

| Global Hub
| Latest stable
| None
| Installed on the target hub cluster only
|===

The following core resources are included in the migration:

ManagedCluster:: Facilitates cluster registration and management.
KlusterletAddonConfig:: Defines add-on configurations for managed clusters.

The following deployment resources are included in the migration:

ClusterDeployment::
Contains Hive deployment configuration while preserving status.
ImageClusterInstall::
Manages image-based installation configuration while preserving status.

The following secrets are included in the migration:

.Secrets included in the migration
|===
| Secret type | Description

| Administrative credentials
| The `<cluster-name>-admin-password` secret.

| Administrative Kubeconfig
| The `<cluster-name>-admin-kubeconfig` secret.

| Metadata
| The `<cluster-name>-metadata-json` secret.

| Seed reconfiguration
| The `<cluster-name>-seed-reconfiguration` secret.

| Network secrets
| Secrets that contain the `siteconfig.open-cluster-management.io/sync-wave` annotation.

| Referenced secrets
| Credentials and pull secrets that the system collects automatically.

| BMC credentials
| Secrets referenced in the `BareMetalHost.spec.bmc.credentialsName` field.

| Pull secrets
| Secrets that are referenced in the `ClusterDeployment.spec.pullSecretRef.name` field.
|===

The following config maps are included in the migration:

Referenced config maps:: Automatically collects config maps that are referenced.
Extra Manifests:: Config maps that are referenced in `ImageClusterInstall.spec.extraManifestsRefs`

The following bare metal resources with status preserved are included in the migration:

BareMetalHost:: Physical server inventory and state
HostFirmwareSettings:: BIOS and firmware configurations
FirmwareSchema:: Firmware setting schemas
HostFirmwareComponents:: Individual firmware components

The following resources are excluded from migration:

ClusterInstance Resources:: Managed by Argo CD, you must manually apply GitOps applications to the target hub cluster after cluster migration.
Policy Resources:: Must be redeployed by GitOps applications on target hub cluster.
Application Resources:: GitOps applications managing cluster configuration.
