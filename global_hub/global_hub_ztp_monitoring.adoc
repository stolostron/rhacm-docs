[#ztp-monitor-migration]
= Monitoring migration progress

[role="_abstract"]
After you start a cluster migration, you can monitor the progress by checking the migration phase and the status of individual clusters. The migration progresses through several distinct phases. You can view the current phase of the migration resource to understand the overall state of the operation.

The migration controller creates a `ConfigMap` to track the status of each cluster involved in the migration. Use this resource to identify which clusters succeeded and which require investigation.

*Required access:* Cluster administrator

.Procedure

. Check the current migration phase by running the following command:

+
[source,bash]
----
oc get managedclustermigration ztp-sno-migration -n multicluster-global-hub
----

. Review the `PHASE` column in the output. The following table describes the possible migration phases:

+
.Migration phases
|===
| Phase | Description
| `Initializing` | The system is preparing the required resources for migration.
| `Deploying` | The system is transferring resources to the target hub cluster.
| `Registering` | The clusters are registering with the target hub cluster.
| `Completed` | The migration finished successfully.
| `RollingBack` | An automatic rollback is in progress because of a detected failure. See _Rolling back cluster migration_ in _Additional resources_.
| `Failed` | The migration failed and requires manual intervention.
|===

. View the migration tracking `configmap` by running the following command:

+
[source,bash]
----
oc get configmap ztp-sno-migration -n multicluster-global-hub -o yaml
----

. Locate the `data` section in the output to see the list of successful and failed clusters. See the following example, where `"sno1","sno3"` clusters migrated successfully and the `"sno2"` cluster failed to migrate and requires further investigation.

+
[source,yaml]
----
data:
  success: '["sno1","sno3"]'
  failure: '["sno2"]' 
----

. See xref:../global_hub/global_hub_ztp_apply_clusterinstance.adoc#ztp-monitor-migration[Applying _ClusterInstance_ applications to the target hub cluster] for information about how to proceed with the successful clusters.

You might need to investigate the failed clusters. See _Rolling back cluster migration_ in _Additional resources_ for information about how to proceed if you encounter failures during migration.
