= Installing {global-hub} on an existing {acm-short} hub cluster

[role="_abstract"]
You can install {global-hub} in an existing {acm-short} hub cluster and enable the {global-hub} agent in {acm-short}. The {global-hub} agent is automatically installed on an existing {acm-short} hub cluster. Learn about the following capabilities: 

* When you install {global-hub} in an {acm-short} hub cluster, Kafka receives the information from the {global-hub} operator and stores it in the {global-hub} database, giving you access to the clusters, policies, and events. 
* Kafka stores the {global-hub} operator information, so as a Kafka consumer, you can access other components. For example, you can integrate with Red Hat Advanced Cluster Security and Red Hat Event-Driven Ansible. 
* Your data is stored in the {global-hub} database so you can view the cluster and policy information in the Grafana dashboards. 

.Procedure

. To install {global-hub} on an existing {acm-short} hub cluster, set the `installAgentOnLocal` field to `true` by applying the following YAML sample:

+
[source,yaml]
----
apiVersion: operator.open-cluster-management.io/v1alpha4
kind: MulticlusterGlobalHub
metadata:
  name: multiclusterglobalhub
  namespace: multicluster-global-hub
spec:
  enableMetrics: true
  installAgentOnLocal: true
  dataLayer:
    kafka:
      topics:
        specTopic: gh-spec
        statusTopic: gh-status
      consumerGroupPrefix: org1_
    postgres:
      retention: 18m
  availabilityConfig: High
----
+
* `installAgentOnLocal`: Deploys {global-hub} on the {global-hub} cluster. If you set the value to `true`, the {global-hub} operator installs the agent on the {global-hub} cluster.
* `specTopic`: Distributes workloads from {global-hub} to managed hub clusters. The default value is `gh-spec`.
* `statusTopic`: Reports events and status updates to the {global-hub} manager. When a topic ends with an asterisk, the topic is intended for the individual managed hub clusters. The default value for all managed hub clusters is `gh-status`.
* `consumerGroupPrefix`: Specifies the prefix for Kafka consumer groups. The final consumer group identification for {global-hub} is `<prefix> + "global_hub"`, and for managed hub clusters it is `<prefix> + <managed-hub-name>`. In the final group identification, all hyphens, get changed to underscores. If you do not specify a value, the default consumer group is the name of the hubs without any prefix.
* `availabilityConfig`: Specifies the replication of deployments to improve their availability. For the values of the replications, you have the options of `Basic` and `High`. For the `High` value, the `availabilityConfig` creates one replica for the {global-hub} manager and Grafana. It creates two replicas for the Kafka broker, which is a separate component in {global-hub}. The default value is `High`.

. Create a `MultiClusterGlobalHub` custom resource by completing the following procedures. If you enabled the `MultiClusterObservability` custom resource in the {acm-short} after you installed {global-hub}, then any new update for the `MultiClusterObservability` custom resource does not take effect.
