= Preparing for ClusterInstance ZTP migration

The Cluster Instance Zero Touch Provisioning (ZTP) migration allows the Multicluster Global Hub to transition cluster management from legacy SiteConfig or BareMetalHost methods to the modern ClusterInstance custom resource.

The migration ensures that managed hubs can handle high-scale environments by standardizing how cluster instances are represented and synchronized across the fleet. This process is essential for maintaining a single point of control while managing a large number of distributed clusters.


A successful migration results in consistent resource definitions, improved scalability, and reduced manual configuration for edge cluster deployments.

When a cluster administrator needs to upgrade management capabilities, they prepare the environment for ClusterInstance migration to ensure compatibility and prevent data loss during the transition.

.Key components
* **Multicluster Global Hub Operator:** Manages the deployment of global hub components.
* **ClusterInstance CR:** The primary resource used to define and manage cluster lifecycles.
* **Managed Hub Agent:** Synchronizes migration states between the global hub and regional hubs.


.Prerequisites
* Red Hat Advanced Cluster Management (RHACM) version 2.9 or later is installed.
* The Multicluster Global Hub operator is running.
* Access to the global hub cluster with `cluster-admin` privileges.

.Procedure
. Log in to the global hub cluster.
. Verify that all managed hubs are in a `Joined` state.
. Back up existing `SiteConfig` and `ManagedCluster` resources.
. Disable any automated reconciliation loops that might conflict with the new `ClusterInstance` definitions.
. Ensure the `OperatorHub` resource has default catalog sources disabled if a restricted network is used:
+
[source,bash]
----
oc patch OperatorHub cluster --type json -p '[{"op": "add", "path": "/spec/disableAllDefaultSources", "value": true}]'
----

.Results
The environment is ready for the creation of ClusterInstance resources.
