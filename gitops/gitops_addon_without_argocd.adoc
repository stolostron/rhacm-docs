[#enable-gitops-addon-without-argocd]
= Enabling {gitops} add-on without the Argo CD Agent

[role="_abstract"]
The `Basic` mode for pull model does not include the Argo CD Agent, so the pull model gives you a simpler setup for your hub cluster management and only gives you the necessary statuses of the health of your hub clusters. This mode enables the {gitops-short} add-on to the managed clusters that you selected with the `Placement` resource. 

After enabling the add-on, the `Basic` mode deploys the {gitops-short} Argo CD components that are suitable for the cluster workflows.

*Important:* The {gitops-short} add-on without the Argo CD Agent (basic pull model) is only supported on {ocp-short} managed clusters. For non-{ocp-short} managed clusters, use the advanced pull model with the Argo CD Agent instead. See xref:../gitops/gitops_addon_with_argocd.adoc#enable-gitops-addon-with-argocd[Enabling {gitops} add-on with Argo CD Agent (Technology Preview)].

To enable basic pull model, create a `GitOpsCluster` resource. The controller automatically creates the following resources for each managed cluster selected by the `Placement` policy: 

* `AddOnDeploymentConfig` resource in the managed cluster namespace
* `ManagedClusterAddOn` resource in the managed cluster namespace

The {gitops} add-on deploys to each selected managed cluster and installs the following resources:

* {gitops-short} operator in the `openshift-gitops-operator` namespace
* Argo CD instance in the  `openshift-gitops` namespace

+
*Notes:* 
- The `ArgoCD` `Policy` resource is created once and is user-owned. You can modify the `Policy` to add RBAC, applications, or customize `ArgoCD` settings. The controller does not automatically update the `Policy` resource after creation.
- By default, the {gitops-short} add-on might not provide sufficient privileges for the {gitops-short} controllers on managed clusters, especially when managing resources other than the `openshift-gitops` namespace. If the {gitops-short} controllers require additional privileges, see the link:https://docs.redhat.com/en/documentation/red_hat_openshift_gitops[{gitops-short} documentation] for details. You can modify the `ArgoCD` `Policy` resource that the `GitOpsCluster` generates to assign additional roles and elevate the privileges for the {gitops-short} controllers.

.Prerequisites

- {acm-short} hub cluster installed
- Managed clusters that are registered with {acm-short}
- {gitops-short} operator that is installed on the hub cluster
- A `Placement` resource that is defined to select target managed clusters
- `ManagedClusterSet` that is bound to the target namespace

.Procedure

To enable {gitops} add-on without the Argo CD Agent create a `GitOpsCluster` resource. Complete the following steps:

. On your hub cluster, create a `GitOpsCluster` resource to enable the {gitops} add-on by adding the following YAML sample:

+
[source,yaml]
----
apiVersion: apps.open-cluster-management.io/v1beta1
kind: GitOpsCluster
metadata:
  name: gitops-clusters
  namespace: openshift-gitops
spec:
  argoServer:
    argoNamespace: openshift-gitops
  placementRef:
    kind: Placement
    apiVersion: cluster.open-cluster-management.io/v1beta1
    name: all-openshift-clusters
    namespace: openshift-gitops
  gitopsAddon:
    enabled: true
----

. Apply the YAML sample by running the following command: 

+
[source,bash]
----
oc apply -f gitopscluster-example.yaml 
----

. To verify the necessary installations and resources for successful deployment, complete the following steps:

.. Verify that the `GitOpsCluster` resource has a status for successful deployment by running the following command: 

+
[source,bash]
----
oc get gitopscluster gitops-clusters -n openshift-gitops -o yaml
----

.. Check the status conditions for specific information by running the following command:

+
[source,bash]
----
oc get gitopscluster gitops-clusters -n openshift-gitops -o jsonpath='{.status.conditions}' | jq
----

.. Verify that the `ArgoCD` `Policy` was created on the hub cluster by running the following command:

+
[source,bash]
----
oc get policy gitops-clusters-argocd-policy -n openshift-gitops
----

.. Check that the {gitops-short} add-on controller is working on the managed cluster by running the following command: 

+
[source,bash]
----
oc get pods -n open-cluster-management-agent-addon
----

.. Verify the {gitops-short} operator is working on the managed cluster by running the following command: 

+
[source,bash]
----
oc get pods -n openshift-gitops-operator
----

.. Verify the `ArgoCD` instance is working on the managed cluster by running the following command:

+
[source,bash]
----
oc get pods -n openshift-gitops
----

[#deprecated-multiclusterapplicationsetreport-basic]
== Deprecated APIs

The `MulticlusterApplicationSetReport` API (`apps.open-cluster-management.io/v1alpha1`) has been deprecated and will be removed in a future release. If you are using this API, plan to migrate to the {gitops} add-on with the advanced pull model (Argo CD Agent). See xref:../gitops/gitops_addon_with_argocd.adoc#enable-gitops-addon-with-argocd[Enabling {gitops} add-on with Argo CD Agent (Technology Preview)].

.Additional resources 

- For {ocp-short} managed clusters, enable a deployment based on {olm}. See xref:../gitops/gitops_enable_olm.adoc#gitops-enable-olm[Enabling a deployment based on {olm}].
- Continue setting up the {gitops-short} add-on by completing xref:../gitops/gitops_manage_addon.adoc#manage-gitops-addon[Managing the {gitops} add-on].
