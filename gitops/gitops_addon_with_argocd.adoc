= Enabling {gitops} add-on with _ArgoCD_ agent (Technology Preview)

The `Agent` mode for the pull model enables the {gitops-short} add-on for `Advanced` pull model with the `ArgoCD` agent to get detailed statuses on the health of your application. Use this `Agent` mode in environments with network restrictions, enhanced security requirements, or when you implement a pull model for application delivery. The advanced pull model is powered by the `ArgoCD` agent and gives you a fully automated {gitops-short} experience.

To enable the {gitops-short} add-on with the `ArgoCD` agent, complete the following sections:

.Prerequisites

* {acm-short} hub cluster installed
* Managed clusters registered with {acm-short}
* {gitops-short} operator installed on the hub cluster
* A `Placement` resource to select target managed clusters
* `ManagedClusterSet` bound to the target namespace
* {gitops-short} operator subscription configured with the `ArgoCD` agent environment
* The `ArgoCD` custom resource that is configured for the `Agent` mode

== Configuring subscriptions and resources

To enable the `ArgoCD` agent, you must configure the {gitops-short} operator subscription and the `ArgoCD` custom resource. To configure the necessary subscriptions and resources, complete the following steps:


. On the hub cluster only, modify the {gitops-short} operator subscription to include the required environment variables by running the following command:

+
[source,bash]
----
oc edit subscription gitops-operator -n openshift-gitops-operator
----

. Add the following environment variables to the `spec.config.env` file by adding the following YAML sample:

+
[source,yaml]
----
spec:
  config:
    env:
    - name: ARGOCD_CLUSTER_CONFIG_NAMESPACES
      value: openshift-gitops
    - name: ARGOCD_PRINCIPAL_TLS_SERVER_ALLOW_GENERATE
      value: "false"
    - name: ARGOCD_PRINCIPAL_REDIS_SERVER_ADDRESS
      value: openshift-gitops-redis:6379
----

. Replace the existing `ArgoCD` custom resource with the compatible `Agent` mode configuration by adding the following YAML sample:


+
[source,yaml]
----
apiVersion: argoproj.io/v1beta1
kind: ArgoCD
metadata:
  name: openshift-gitops
  namespace: openshift-gitops
spec:
  controller:
    enabled: false
  sourceNamespaces:
  - '*'
  argoCDAgent:
    principal:
      enabled: true
      auth: mtls:CN=system:open-cluster-management:cluster:([^:]+):addon:gitops-addon:agent:gitops-addon-agent
      namespace:
        allowedNamespaces:
        - '*'
      server:
        route:
          enabled: true
----

. Apply the YAML sample by running the following command:

+
[source,bash]
----
oc apply -f argocd-example.yaml
----

* *Note:* On the hub cluster only, this configuration disables the traditional `ArgoCD` controller and enables the agent principal with mutual TLS authentication. The `sourceNamespaces` field with `*` allows applications from any namespace. The `server.route.enabled` field creates an {ocp-short} Route for the agent principal, which is used for agent-to-hub communication.

== Enabling _ArgoCD_ agent

Create a `GitOpsCluster` resource to manage the `ArgoCD` agent add-on deployment. The controller automatically creates the following resources for each managed cluster selected by the `Placement`:

* `AddOnDeploymentConfig` resource in the managed cluster namespace
* `ManagedClusterAddOn` resource in the managed cluster namespace
* Dynamic `AddOnTemplate` for the `ArgoCD` agent mode
* `ArgoCD` cluster secrets configured for agent mode
* TLS certificates for agent-to-hub authentication
* `ManifestWork` resources to propagate hub CA certificates to managed clusters

The `GitOpsCluster` controller also performs automated PKI management and deploys the `ArgoCD` agent on each selected managed cluster.

To enable the advanced pull model `ArgoCD` agent architecture, complete the following steps:

. On your hub cluster, create a `GitOpsCluster` resource with the `ArgoCD` agent enabled by adding the following YAML sample:

+
[source,yaml]
----
apiVersion: apps.open-cluster-management.io/v1beta1
kind: GitOpsCluster
metadata:
  name: gitops-agent-clusters
  namespace: openshift-gitops
spec:
  argoServer:
    argoNamespace: openshift-gitops
  placementRef:
    kind: Placement
    apiVersion: cluster.open-cluster-management.io/v1beta1
    name: production-clusters
    namespace: openshift-gitops
  gitopsAddon:
    enabled: true
    argoCDAgent:
      enabled: true
      mode: managed
----

+
The `mode` field determines the agent operation mode. The default value is `managed`. If you want to change the mode to `autonomous`, set the `mode` field to `autonomous` in the `argoCDAgent` specification. The only valid values are `managed` and `autonomous`. For more information about agent operation modes, see the {gitops-short} documentation.

+
*Note:* For {ocp-short} managed clusters, it is strongly recommended to enable OLM-based deployment by adding `olmSubscription.enabled: true` to the `gitopsAddon` specification. For more information, see xref:../gitops/gitops_manage_addon.adoc#manage-gitops-addon[Managing the {gitops} add-on].

. Apply the YAML sample by running the following command:

+
[source,bash]
----
oc apply -f gitopscluster-example.yaml
----

. The controller automatically discovers the `ArgoCD` agent principal server address from the {ocp-short} Route. You can verify the discovered address by running the following command:

+
[source,bash]
----
oc get gitopscluster gitops-agent-clusters -n openshift-gitops -o jsonpath='{.spec.gitopsAddon.argoCDAgent.serverAddress}'
----

+
*Note:* If you need to override auto-discovery for non-standard setups, you can manually specify `serverAddress` and `serverPort` in the `argoCDAgent` specification.

== Verifying the _ArgoCD_ installation

After the `ArgoCD` agent is successfully deployed, verify the advanced `Pull Model` workflow is completed by creating an application on the hub cluster and confirming it works on the managed cluster.

To verify the necessary installations and resources for successful deployment, complete the following steps:

. Check the `GitOpsCluster` status for specific `Agent` conditions by running the following command:

+
[source,bash]
----
oc get gitopscluster gitops-agent-clusters -n openshift-gitops -o jsonpath='{.status.conditions}' | jq
----

. Confirm that you see the following condition types in the status:

+
* `Ready`: The `GitOpsCluster` is ready and all the components are functioning.
* `PlacementResolved`: The `Placement` reference is resolved and the managed clusters are retrieved.
* `ArgoServerVerified`: The `ArgoCD` server pod was found in the specified namespace.
* `ClustersRegistered`: The managed clusters are successfully registered with the `ArgoCD` server.
* `AddOnDeploymentConfigsReady`: The `AddOnDeploymentConfigs` are created for all the managed clusters.
* `ManagedClusterAddOnsReady`: The `ManagedClusterAddOns` are created and updated for the managed clusters.
* `AddOnTemplateReady`: The dynamic `AddOnTemplate` is created for the `ArgoCD` agent mode.
* `ArgoCDAgentPrereqsReady`: The agent prerequisites are set up, including JWT secrets and configuration.
* `GitOpsAddonPrereqsReady`: The addon prerequisites are set up, including RBAC resources and CA secrets.
* `CertificatesReady`: The TLS certificates are signed and ready for use.
* `ManifestWorksApplied`: The CA certificates are propagated to managed clusters.
* `ArgoCDPolicyReady`: The `ArgoCD` `Policy` is created for managing the `ArgoCD` custom resource on managed clusters.

. Verify the agent principal is running on the hub cluster by running the following command:

+
[source,bash]
----
oc get pods -n openshift-gitops -l app.kubernetes.io/name=openshift-gitops-agent-principal
----

. Create an `ArgoCD` application resource in the managed cluster namespace on the hub cluster by adding the following YAML file:

+
[source,yaml]
----
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: guestbook
  namespace: <managed-cluster-name>
spec:
  project: default
  source:
    repoURL: https://github.com/argoproj/argocd-example-apps.git
    targetRevision: HEAD
    path: guestbook
  destination:
    server: https://<principal-server-address>:<port>?agentName=<managed-cluster-name>
    namespace: guestbook
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
    - CreateNamespace=true
----

+
*Note:* The `<principal-server-address>` and `<port>` values are automatically discovered and stored in the `ArgoCD` cluster secret. You can retrieve the server URL from the cluster secret by running the following command:

+
[source,bash]
----
oc get secret cluster-<managed-cluster-name> -n openshift-gitops -o jsonpath='{.data.server}' | base64 -d
----

. Apply the YAML sample by running the following command:

+
[source,bash]
----
oc apply -f application-example.yaml
----

. On the managed cluster, verify that the application resources are deployed by running the following command:

+
[source,bash]
----
oc get all -n guestbook
----

. On the hub cluster, verify the application status is reflected back to you by running the following command:

+
[source,bash]
----
oc get application guestbook -n <managed-cluster-name>
----

. Confirm that the status shows `Synced` when the application is successfully deployed.
