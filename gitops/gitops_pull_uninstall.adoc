[#gitops-pull-uninstall]
= Uninstall the {gitops-short} add-on

[role="_abstract"]
Uninstall the {gitops} add-on in the correct order so that dependencies and finalizers are cleaned up successfully.

*Important:* The uninstall takes several minutes. Do not force-remove finalizers before the cleanup completes. You must complete the uninstall in the correct order due to resource dependencies.

*Required access:* Cluster administrator

.Procedure

. Delete any `ApplicationSet` resources and wait for the generated `Application` resources to be removed. Run the following command. Replace `<applicationset-name>` with the name of your `ApplicationSet`:

+
[source,bash]
----
oc delete applicationset <applicationset-name> -n openshift-gitops --ignore-not-found
----

. Verify that all generated `Application` resources are removed. Run the following command:

[source,bash]
----
oc get applications.argoproj.io -n openshift-gitops
----

. Delete the `Placement` resources by running the following commands. Replace `<gitops-placement-name>` and `<app-placement-name>` with the names of your `Placement` resources:

+
[source,bash]
----
oc delete placement <gitops-placement-name> -n openshift-gitops --ignore-not-found
oc delete placement <app-placement-name> -n openshift-gitops --ignore-not-found
----

. Delete the `GitOpsCluster` resource by running the following command. Replace `<name>` with the name of your `GitOpsCluster`:

+
[source,bash]
----
oc delete gitopscluster <name> -n openshift-gitops --ignore-not-found
----

. Delete the auto-generated `Policy` and `PlacementBinding` resources. Run the following commands. Replace `<name>` with the name of your `Policy` and `PlacementBinding`:

+
[source,bash]
----
oc delete policy <name>-argocd-policy -n openshift-gitops --ignore-not-found
oc delete placementbinding <name>-argocd-policy-binding -n openshift-gitops --ignore-not-found
----
+
*Important:* If the `Policy` is not deleted, it continues to enforce the `ArgoCD` custom resource on managed clusters even after the add-on is removed. If the controller recreates the `Policy` before the `GitOpsCluster` is fully removed, delete the `Policy` and `PlacementBinding` again by repeating this step.

. Wait for the `ArgoCD` custom resource to be removed from each managed cluster. Monitor the removal. Run the following command. Replace `<managed-cluster-context>` with the context of the managed cluster:

+
[source,bash]
----
oc get argocd acm-openshift-gitops -n openshift-gitops --context <managed-cluster-context>
----

. For {ocp-short} managed clusters with {olm}-based deployment, verify that the {olm} `Subscription` created by the add-on is also removed. Run the following command. Replace `<managed-cluster-context>` with the context of the managed cluster:

+
[source,bash]
----
oc get subscription.operators.coreos.com -l apps.open-cluster-management.io/gitopsaddon=true -A --context <managed-cluster-context>
----

. If you enabled agent mode, delete the hub cluster agent resources. Run the following commands. Replace `<managed-cluster-name>` with the name of the managed cluster:

+
[source,bash]
----
oc delete appproject --all -n <managed-cluster-name> --ignore-not-found
oc delete secret cluster-<managed-cluster-name> -n openshift-gitops --ignore-not-found
oc delete secret <managed-cluster-name>-application-manager-cluster-secret -n openshift-gitops --ignore-not-found
----

. Delete the `ManagedClusterSetBinding`. Run the following command:

+
[source,bash]
----
oc delete managedclustersetbinding default -n openshift-gitops --ignore-not-found
----

*Consequences of improper uninstall:*

* *`Policy` not deleted*: The `Policy` continues to enforce the `ArgoCD` CR on managed clusters, causing the operator and Argo CD to be re-created even after the add-on is removed.
* *`PlacementBinding` not deleted*: The `PlacementBinding` keeps the `Policy` bound to the `Placement`, making re-enforcement more likely.
* *Finalizers not cleared*: Residual `Application` resources with finalizers can block namespace deletion. If needed, patch the finalizer: `oc patch application <name> -n openshift-gitops --type=json -p '[{"op":"remove","path":"/metadata/finalizers"}]'`.
* *Application workload namespaces* (for example, `guestbook`) are not cleaned up by the add-on. Delete them manually if needed.
* *`ClusterRoleBinding` leftovers*: If you added custom `ClusterRoleBinding` resources (for example, `acm-openshift-gitops-cluster-admin`) via the `Policy`, they remain on managed clusters after uninstall. Delete them manually if needed.
