= _ManifestWork_-based pull model overview

The `ManifestWork`-based pull model uses the {gitops} add-on to install the {gitops-short} operator and an Argo CD instance on each managed cluster. Each instance synchronizes from Git repositories independently.

The propagation controller on the hub cluster distributes `Application` resources to managed clusters by using the `ManifestWork` resource. The hub cluster shows an overview of the health and synchronization status for each application.

After you enable the `ManifestWork`-based pull model, the controller creates an `ArgoCD` `Policy` named `<gitopscluster-name>-argocd-policy` that deploys and configures the `ArgoCD` custom resource on managed clusters through the {acm-short} governance framework.

The policy is user-owned after creation. You can modify the policy for RBAC or `ArgoCD` settings. The controller does not overwrite your customizations.

*Important notes:*

* The `ManifestWork`-based pull model is only supported on {ocp-short} managed clusters. For managed clusters that are not {ocp-short}, use the Argo CD Agent-based pull model.
* If you need full Argo CD user interface compatibility with real-time resource trees, logs, and detailed status from managed clusters, use the Argo CD Agent-based pull model instead.
* {gitops-short} requires an *{ocp}* subscription. {acm-short} does not include this entitlement. See link:https://www.redhat.com/en/resources/self-managed-openshift-subscription-guide[Self-Managed OpenShift Subscription Guide] for more information.
