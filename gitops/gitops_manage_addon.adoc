= Managing the {gitops} add-on

The {gitops-short} add-on automates the deployment and lifecycle management of {gitops-short} on managed clusters. Based on your architecture and connectivity requirements, decide if you want to deploy the GitOps add-on with the `ArgoCD` agent component. Otherwise, you can deploy the {gitops-short} add-on without the `ArgoCD` agent.

*Important:* If you enable the {gitops-short} add-on by using the `GitOpsCluster` custom resource, then the `GitOpsCluster` disables the `Push Model` for all applications.

When you enable the {gitops-short} add-on, you have the following deployment modes:

* `Basic` mode: Deploys the {gitops-short} operator and an `ArgoCD` instance on managed clusters through the `GitOpsCluster` custom resource. For {ocp-short} managed clusters, it is strongly recommended to enable OLM-based deployment by setting `olmSubscription.enabled: true`.

* `Agent` mode: Includes all `Basic` mode components along with the `ArgoCD` agent for enhanced pull-based architecture (Technology Preview).

To enable the {gitops-short} add-on for your selected managed clusters, reference your `Placement` and use the `GitOpsCluster` custom resource as the interface for enabling.

*Note:* When the {gitops-short} add-on is enabled, the `GitOpsCluster` controller creates an `ArgoCD` `Policy` on the hub cluster. This `Policy` deploys the `ArgoCD` custom resource to managed clusters through the {acm-short} policy framework. The `Policy` is created once and is user-owned, which means you can modify the `Policy` to add RBAC, applications, or customize `ArgoCD` settings. The controller does not automatically update the `Policy` after creation.

*Important:* By default, the {gitops-short} add-on might not provide sufficient privileges for the {gitops-short} controllers on managed clusters, especially when managing resources outside the `openshift-gitops` namespace. If the {gitops-short} controllers require additional privileges, see the link:https://docs.redhat.com/en/documentation/red_hat_openshift_gitops[{gitops-short} documentation] for details. You can modify the `ArgoCD` `Policy` that the `GitOpsCluster` generates to assign additional roles and elevate the privileges for the {gitops-short} controllers.

.Prerequisites

If you want to enable the {gitops-short} add-on with the `ArgoCD` agent, use the `Agent` mode. See xref:../gitops/gitops_addon_with_argocd.adoc#enable-gitops-addon-with-argocd[Enabling {gitops} add-on with _ArgoCD_ agent (Technology Preview)]

If you want to enable the {gitops-short} add-on without the `ArgoCD` agent, use the `Basic` mode. See xref:../gitops/gitops_addon_without_argocd.adoc#enable-gitops-addon-without-argocd[Enabling {gitops} add-on without the _ArgoCD_ agent]


== Configuring {gitops-short} add-on settings

The {gitops-short} add-on supports various configuration options to customize the deployment according to your requirements.

The {gitops-short} add-on supports the following configuration options in the `gitopsAddon` specification:

* `enabled`: Enable or disable the GitOps add-on. The default is `false`.
* `gitOpsOperatorImage`: Custom container image for the GitOps operator. This is the only image that needs to be specified. All other component images, such as `ArgoCD`, `Redis`, and `Repo Server`, are determined by the operator.
* `overrideExistingConfigs`: Override existing `AddOnDeploymentConfig` values with new values from the `GitOpsCluster` specification. Must be set to `true` when performing any uninstall operation. The default is `false`.
* `argoCDAgent`: `ArgoCD` agent configuration sub-section (Technology Preview).
* `olmSubscription`: OLM `Subscription` configuration sub-section. For {ocp-short} managed clusters, it is strongly recommended to enable OLM-based deployment. Set `olmSubscription.enabled` to `true` to enable.

The `ArgoCD` agent supports the following configuration options in the `argoCDAgent` specification (Technology Preview):

* `enabled`: Enable or disable the agent. The default is `false`.
* `propagateHubCA`: Propagate hub certified authority (CA) certificate to managed clusters. The default is `true`.
* `serverAddress`: Override the `ArgoCD` agent principal server address. When empty, the controller automatically discovers the address from the {ocp-short} Route.
* `serverPort`: Override the `ArgoCD` agent principal server port. When empty, the controller automatically discovers the port.
* `mode`: Agent operation mode. Valid values are `managed` and `autonomous`. The default is `managed`. To use the `autonomous` mode, set `mode` to `autonomous` in the `argoCDAgent` specification of the `GitOpsCluster` resource. For more information about agent operation modes, see the {gitops-short} documentation.

To configure the {gitops-short} add-on setting, complete the following steps on your hub cluster:

. Customize the container image for the {gitops-short} operator by adding the YAML sample with the `GitOpsCluster`:

+
[source,yaml]
----
apiVersion: apps.open-cluster-management.io/v1beta1
kind: GitOpsCluster
metadata:
  name: gitops-custom-images
  namespace: openshift-gitops
spec:
  argoServer:
    argoNamespace: openshift-gitops
  placementRef:
    kind: Placement
    apiVersion: cluster.open-cluster-management.io/v1beta1
    name: all-openshift-clusters
    namespace: openshift-gitops
  gitopsAddon:
    enabled: true
    gitOpsOperatorImage: "registry.redhat.io/openshift-gitops-1/gitops-operator@sha256:..."
----

. Apply the YAML sample by running the following command:

+
[source,bash]
----
oc apply -f gitopscluster-example.yaml
----

. For {ocp-short} managed clusters, it is strongly recommended to enable OLM-based deployment. Add the `olmSubscription` section to the `GitOpsCluster` with the following YAML:

+
[source,yaml]
----
apiVersion: apps.open-cluster-management.io/v1beta1
kind: GitOpsCluster
metadata:
  name: gitops-olm-deployment
  namespace: openshift-gitops
spec:
  argoServer:
    argoNamespace: openshift-gitops
  placementRef:
    kind: Placement
    apiVersion: cluster.open-cluster-management.io/v1beta1
    name: all-openshift-clusters
    namespace: openshift-gitops
  gitopsAddon:
    enabled: true
    olmSubscription:
      enabled: true
----

. Apply the YAML sample by running the following command:

+
[source,bash]
----
oc apply -f gitopscluster-example.yaml
----
