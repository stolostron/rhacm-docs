[#gitops-pull-agent]
= Argo CD with the Argo CD Agent-based pull model overview

[role="_abstract"]
Use the Argo CD Agent-based pull model to enable the {gitops} add-on with the Argo CD Agent. Like the `ManifestWork`-based pull model, this mode installs the {gitops-short} operator and an independent Argo CD instance on each managed cluster.

Additionally, the principal and agent architecture enables the hub cluster Argo CD user interface to show real-time Application status, resource trees, and logs from all managed clusters.

The Argo CD Agent-based pull model provides the same Argo CD user interface experience as the Push model, while keeping the security and network benefits of the pull architecture.

*Important:* The Argo CD Agent requires a Red Hat OpenShift Platform Plus subscription. {acm-short} does not include this entitlement. See link:https://www.redhat.com/en/resources/self-managed-openshift-subscription-guide[Self-Managed OpenShift Subscription Guide] for more information.

The Argo CD Agent-based pull model uses a principal and agent architecture:

Principal hub cluster:: Runs in the `openshift-gitops` namespace on the hub. It receives connections from agents, dispatches applications, and aggregates status.
Agent managed cluster:: Runs on each managed cluster. It connects to the principal, receives application specs in managed mode, or synchronzies local applications back to the hub cluster inmautonomous mode.
Application controller managed cluster:: Reconciles applications locally on each managed cluster, regardless of mode.

The principal uses destination-based mapping to route applications to the correct agent based on `destination.name`.

See the following table to learn about the differences between managed and autonomous modes:

.Table comparing managed and autonomous mode
[options="header"]
|===
| Aspect | Managed mode | Autonomous mode

| Source of truth
| Principal hub cluster
| Managed cluster

| Application creation
| On the hub cluster. The principal dispatches applications to agents.
| On the managed cluster by using a Policy or Git.

| Application reconciliation
| Local on managed cluster.
| Local on managed cluster. The agent synchronizes specs and status to the hub cluster.

| Hub cluster capability
| Full control. Create, modify, and delete applications.
| Read-only mirror. Inspect only applications.
|===
