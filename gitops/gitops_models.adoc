[#gitops-models]
= Understanding the Push and Pull models

[role="_abstract"]
Compare the Push and Pull models for Argo CD with {acm}, including the advanced and basic Pull variants, and confirm the subscription that each option requires.

You can use {gitops} with {acm} in two primary ways: the *Pull model* and the *Push model*. Choose a model based on your network topology, security requirements, and how much status detail you need on the hub cluster.

*Important:* {acm-short} does *not* include entitlements for {gitops-short}. You must have a separate OpenShift subscription for the features that you use:

* {gitops} (excluding the Argo CD Agent) requires an *{ocp}* subscription.
* The Argo CD Agent requires a *Red Hat OpenShift Platform Plus* subscription. The Argo CD Agent can run on {ocp-short} or on supported Kubernetes environments.

For more information, see the link:https://www.redhat.com/en/resources/self-managed-openshift-subscription-guide[Self-managed Red Hat OpenShift subscription guide].

[options="header"]
|===
| Model | Description | `ApplicationSet` template key | Best for | Subscription

| *Pull* - Advanced ({gitops} add-on with Argo CD Agent)
| The add-on installs the {gitops-short} operator and an Argo CD instance on each managed cluster. A principal and agent architecture enables the hub Argo CD UI to show full, real-time Application status, resource trees, and logs.
| `destination.name: '\{\{name\}\}'`
| Independent cluster GitOps, network-restricted environments, enhanced security, and full Argo CD UI on the hub
| Red Hat OpenShift Platform Plus (Argo CD Agent)

| *Pull* - Basic ({gitops} add-on)
| The add-on installs the {gitops-short} operator and an Argo CD instance on each managed cluster. The propagation controller distributes Application resources by using `ManifestWork`. The hub shows aggregated overall health and sync status only.
| `destination.server: https://kubernetes.default.svc` with pull annotations
| Independent cluster GitOps, network-restricted environments, and enhanced security
| {ocp}

| *Push*
| The Argo CD server on the hub cluster deploys application resources directly on the managed clusters. Managed clusters do not run their own Argo CD instances.
| `destination.server: '\{\{server\}\}'`
| Simple setups and small fleets
| {ocp}
|===
