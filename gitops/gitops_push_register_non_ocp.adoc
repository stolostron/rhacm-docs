= Register non-{ocp-short} clusters to the {gitops} operator

[role="_abstract"]
Register non-{ocp-short} managed clusters with the Argo CD server on the hub cluster so that you can deploy applications to managed clusters.

*Note:* Registering non-{ocp-short} clusters to the {gitops} operator is only available for the Push model.

*Required access:* Cluster administrator

.Prerequisites

* Install the {gitops} operator on your {acm-short} hub cluster.
* Import one or more managed clusters.
* Create a `ManagedClusterSet` and bind it to the namespace where {gitops-short} is deployed. See xref:../clusters/cluster_lifecycle/create_clusterset.adoc#creating-a-managedclusterset[Creating a _ManagedClusterSet_] and xref:../clusters/cluster_lifecycle/create_clustersetbinding.adoc#creating-managedclustersetbinding[Creating a _ManagedClusterSetBinding_ resource].
* Enable the `ManagedServiceAccount` add-on to rotate the token that the Argo CD Push model uses to connect to the managed cluster.

.Procedure

. Create a `Placement` resource for the `GitOpsCluster` to select which managed clusters to register. Add the following YAML sample:

+
[source,yaml]
----
apiVersion: cluster.open-cluster-management.io/v1beta1
kind: Placement
metadata:
  name: gitops-placement
  namespace: openshift-gitops
spec:
  tolerations:
  - key: cluster.open-cluster-management.io/unreachable
    operator: Exists
  - key: cluster.open-cluster-management.io/unavailable
    operator: Exists
  predicates:
  - requiredClusterSelector:
      labelSelector:
        matchExpressions:
        - key: vendor
          operator: "In"
          values:
          - OpenShift
        - key: local-cluster
          operator: DoesNotExist
----

. Apply the YAML sample. Run the following command:

+
[source,bash]
----
oc apply -f placement.yaml
----

. Create a `GitOpsCluster` custom resource to register the managed clusters. Addthe following YAML sample:

+
[source,yaml]
----
apiVersion: apps.open-cluster-management.io/v1beta1
kind: GitOpsCluster
metadata:
  name: gitops-cluster-push
  namespace: openshift-gitops
spec:
  argoServer:
    argoNamespace: openshift-gitops
  placementRef:
    kind: Placement
    apiVersion: cluster.open-cluster-management.io/v1beta1
    name: gitops-placement
----

. Apply the YAML sample. Run the following command:

+
[source,bash]
----
oc apply -f gitops-cluster-push.yaml
----
+
*Note:* The `GitOpsCluster` controller automatically creates the following resources during reconciliation:
+
* The `acm-placement` duck-type `ConfigMap` in the `argoServer.argoNamespace`
* A `Role` and `RoleBinding`
* An `ArgoCD` `Policy` named `<gitopscluster-name>-argocd-policy`

. If the API server URL in the `ManagedCluster` resource `spec` is empty, update it manually. Run the following command. Replace `<cluster-name>` with the name of the managed cluster:

+
[source,bash]
----
oc edit managedclusters <cluster-name>
----

. Verify that the `spec` includes the client configuration. See the following example:

+
[source,yaml]
----
spec:
  managedClusterClientConfigs:
  - caBundle: <base64-encoded-ca>
    url: https://<api-server-url>
----

== {gitops} token

*Note:* The token and cluster secret mechanisms described in this section are for the Push model only.

When you integrate with the {gitops-short} operator, for every managed cluster bound through the placement and `ManagedClusterSetBinding`, a secret with a token to access the `ManagedCluster` is created in the {gitops-short} namespace. The secure cluster secrets are rendered based on the following priority order:

*Cluster proxy service:* The default option because the `cluster-proxy` add-on is always enabled in multicluster engine operator. Secrets include the cluster proxy URL, service CA, and `ManagedServiceAccount` `application-manager` token.

*Managed cluster client configurations:* If the cluster proxy is unavailable. Secrets include the API server URL and CA from the managed cluster specification, plus the same `ManagedServiceAccount` token.

If you do not want the default service account, see xref:../gitops/gitops_push_service_account.adoc#gitops-push-service-account[Create a customized service account for Argo CD Push model].
