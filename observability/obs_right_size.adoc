= Optimizing workloads by using right-sizing (Technology Preview)

The right-sizing feature compares real-time CPU and memory usage with the resource configuration that you set and offers suggestions to optimize workloads on a namespace and cluster level.

With right-sizing, you can use infrastructure more efficiently, reduce costs, and ensure better performance across workloads by identifying over-provisioned or under-utilized resources across managed clusters.

*Required access:* Editor

[#right-size-prereq]
== Prerequisites

- The multicluster observability operator is enabled on the hub cluster.

[#enable-right-size-prereq]
== Enabling right-sizing

You can implement right-sizing by enabling the feature in the `MultiClusterObservability` custom resource on the hub cluster. Complete the following steps:

. Open the observability instance configuration. Run the following command:

+
[source,bash]
----
oc edit multiclusterobservability observability
----

. Add the following lines to the `spec` section of your `MultiClusterObservability` custom resource:

+
[source,yaml]
----
apiVersion: observability.open-cluster-management.io/v1beta2
kind: MultiClusterObservability
metadata:
  name: observability
spec:
  capabilities:
    platform:
      analytics:
        namespaceRightSizingRecommendation:
          enabled: true
. . .
----
+
You can set `enabled:` to `false` to disable right-sizing.

After enabling right-sizing, the following resources are created automatically:

The `rs-namespace-config` `ConfigMap`:: Stores configurations for placement and `PrometheusRule`.
The `rs-prom-rules-policy` `Policy`:: Contains the Prometheus rules to evaluate resource usage.
The 
The `rs-placement` `Placement`:: Determines target clusters based on label selectors.
The 
The `rs-policyset-binding` `PlacementBinding`:: Binds the policy and placement together.

You can view right-sizing suggestions by accessing *RightSizing Recommendation* > *ACM Right-Sizing Namespace* from your Grafana dashboard.

*Notes:*

* Prometheus rules are based on the cluster name, not on the cluster ID.
* The CPU and memory request, utilization, and suggestion metrics show maximum values based on the last number of aggregated days you select.
* Historical data points are not backfilled. After you install the right-sizing feature, you need to wait to investigate longer aggregation periods.
