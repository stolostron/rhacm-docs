= Enabling right-sizing for Virtualization workloads (Technology Preview)

//decided to not add the same intro as the "Optimizing workloads..." section bc it's repetitive; we can discuss with doc arch

Enable right-sizing for Virtualization to help you identify over-provisioned or under-utilized virtual machine resources across managed clusters.

You can implement right-sizing by enabling the feature in the `MultiClusterObservability` custom resource on the hub cluster. 

.Prerequisites

- The multicluster observability operator is enabled on the hub cluster.
- *Required access:* Editor

Complete the following steps to enable right-sizing for your virtual machines:

. Open the observability instance configuration. Run the following command:

+
[source,bash]
----
oc edit multiclusterobservability observability
----

. Add the following lines to the `spec` section of your `MultiClusterObservability` custom resource:

+
[source,yaml]
----
apiVersion: observability.open-cluster-management.io/v1beta2
kind: MultiClusterObservability
metadata:
  name: observability
spec:
  capabilities:
    platform:
      analytics:
        virtualizationRightSizingRecommendation:
          enabled: true
. . .
----
+
You can set the `enabled:` parameter for `virtualizationRightSizingRecommendation` to `false` to disable right-sizing for Virtualization.

After enabling right-sizing, the following resources are created automatically:

The `rs-virt-config` `ConfigMap`:: Stores virtual machine configurations for placement and `PrometheusRule`.
The `rs-prom-rules-policy` `Policy`:: Contains the Prometheus rules to evaluate resource usage.
The 
The `rs-placement` `Placement`:: Determines target clusters based on label selectors.
The 
The `rs-policyset-binding` `PlacementBinding`:: Binds the policy and placement together.

. View right-sizing guides by accessing *RightSizing Recommendation* > *ACM Right-Sizing Namespace* from your Grafana dashboard.
.. To change your view of the data on Grafana, click the drop-down arrow for a list and select the data type that you want to display. For example, change the view from CPU data to memory data by clicking the drop-down arrow and select *Memory*.

*Notes:*

* Prometheus rules are based on the cluster name, not on the cluster ID.
* The CPU and memory request, utilization, and guide metrics show maximum values based on the last number of aggregated days you select.
* Historical data points are not backfilled. After you install the right-sizing feature, you need to wait to investigate longer aggregation periods.
