= Multicluster Observability add-on

Use the multicluster observability add-on to configure metrics collection by using names, matchers, and recording rules for both platform and user workloads. Edit your `ClusterManagementAddOn` resource, scale metric federation, and improve peformance and reduce data loss during network partitions between your managed and hub clusters.

[#managed-cluster-workloads]
== Managed cluster workloads

Managed cluster monitoring workloads use the Prometheus Operator and Prometheus Agent from the cluster observability operator. This integration provides the following benefits:

- Consistent lifecycle management for Prometheus components across managed clusters.
- Built-in configuration hooks and custom resources tailored for multicluster operation.
- A lightweight Prometheus Agent deployment model for remote-write scenarios.

MCOA utilizes the existing `obo-prometheus-operator` from COO on a managed cluster to reconcile Prometheus custom resources. If obo-prometheus-operator is not present, MCOA deploys it within the configured agentInstallNamespace. Both MCOA and COO share the `monitoring.rhobs` API Group for their `ScrapeConfig`` and `PrometheusAgent` resources.

For other managed clusters that are not OpenShift clusters the following resources are deployed:

- Node exporter
- Kube state metrics
- Prometheus server


[#mcoa-configurable-apis]
== Configurable APIs

To control monitoring behavior on your managed clusters, you can configure the `PrometheusAgent`, `ScrapeConfig`, and `PrometheusRule` custom resource definitions. View the following descriptions of each API:

PrometheusAgent::
- Defines an agent-focused Prometheus deployment optimized for remote-write workflows.
- Typical configuration points: remoteWrite targets, scrape intervals, and resource limits.

ScrapeConfig::
- Declarative scrape definitions for targets and discovery mechanisms.
- Configure job_name, metrics_path, scheme, relabel_configs, and TLS settings.

PrometheusRule::
- Alerting and recording rule definitions that can be applied for each cluster or each tenant.
- Supports groups of rules with evaluation intervals and alert annotations/labels.

AddonDeploymentConfig::

ClusterManagementAddOn:: resources can include an `AddonDeploymentConfig` to customize the deployment of the multicluster observability add-on on managed clusters. You can use this configuration to set resource requests and limits for the Prometheus Agent pods deployed on managed clusters.

== Getting started

1. Install the Multicluster Observability add-on via the operator install path for your environment.
2. Create or edit PrometheusAgent, ScrapeConfig, and PrometheusRule resources in the managed cluster namespace(s).
3. Verify agent connectivity to remote-write endpoints and validate rule evaluations using the COO status and logs.

For details on field schemas and examples, consult the operator CRD documentation provided with your COO release.
