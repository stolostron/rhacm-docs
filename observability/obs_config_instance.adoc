[#configure-obs-instance-size]
= Changing observability instance sizes

[role="_abstract"]
The observability instance sizes feature simplifies the scaling process for {acm} observability. With T-shirt sizing, you can scale all components to preconfigured settings instead of scaling each component individually.

The instance size feature is optional.

*Required access:* Cluster administrator

.Prerequisites

- Your hub cluster needs sufficient CPU and memory resources for the instance size that you want to use. See xref:../observability/obs_instance_sizes.adoc#supported-obs-instance-sizes[Supported observability instance sizes] for more information.
- You must correctly configure persistent volumes for stateful components such as `alertmanager`, `thanos-compactor`, and `thanos-receive`.

.Procedure

To apply a size, edit the `MultiClusterObservability` custom resource on your hub cluster. Complete the following step:

. Add the instance size that you want to use to the `spec.instanceSize` field in the `MultiClusterObservability` custom resource. See the following YAML sample:

+
[source,yaml]
----
apiVersion: observability.open-cluster-management.io/v1beta2
kind: MultiClusterObservability
metadata:
  name: observability
spec:
  instanceSize: <size_value>
----

+
* For a list of valid `spec.instanceSize` options, see xref:../observability/obs_instance_sizes.adoc#supported-obs-instance-sizes[Supported observability instance sizes].

.Verification

After applying a new size, you can verify the status and instance size of the observability pods in the console.
