[#restore-backup]
= Restoring a backup

[role="_abstract"]
In a typical restore situation, the hub cluster where the backups run becomes unavailable, and you need to move the backed up data to a new hub cluster. Run the cluster restore operation on the new hub cluster. In this case, the restore operation runs on a different hub cluster than where the backup is created.

If you want to restore the data on the same hub cluster where the backup was collected, recover the data from an earlier snapshot. In this case, both restore and backup operations run on the same hub cluster.

To fully restore a backup, complete the following: 

.Procedure

. Use the restore operation for backup types. See xref:../backup_restore/backup_restore_types.adoc#restoring-backup-restore-operation[Using the restore operation for backup types].
. Prepare the new hub cluster. See xref:../backup_restore/backup_restore_prepare.adoc#prepare-new-hub[Preparing the new hub cluster].
. Clean the hub cluster after restore. See xref:../backup_restore/backup_restore_cleanup.adoc#clean-hub-restore[Cleaning the hub cluster after restore].
. Restore passive resources. See xref:../backup_restore/backup_restore_passive.adoc#restore-passive-resources-check-backups[Restoring passive resources while checking for backups].
. Restore activation resources. See xref:../backup_restore/backup_restore_activation.adoc#restore-activation-resources[Restoring activation resources].
. Restore imported managed clusters. See xref:../backup_restore/backup_restore_imported.adoc#restore-imported-managed-clusters[Restoring imported managed clusters].
. Use other restore samples. See xref:../backup_restore/backup_restore_samples.adoc#more-restore-samples[Using other restore samples].
