[#restore-restic-backup]
= Restore a Restic backup

[role="_abstract"]
To restore copied data from a Restic backup into a new persistent volume claim, create the claim and a `ReplicationDestination` that points to that claim.

.Procedure

. Create a new persistent volume claim to contain the restored data, similar to the following example:

+
[source,yaml]
----
kind: PersistentVolumeClaim
apiVersion: v1
metadata:
  name: <pvc-name>
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 3Gi
----
+
Replace `pvc-name` with the name of the new persistent volume claim.
+
*Note:* Restore only one backup into a new persistent volume claim.

. Create a `ReplicationDestination` custom resource that resembles the following example to specify where to restore the data:

+
[source,yaml]
----
apiVersion: volsync.backube/v1alpha1
kind: ReplicationDestination
metadata:
  name: <destination>
spec:
  trigger:
    manual: restore-once
  restic:
    repository: <restic-repo>
    destinationPVC: <pvc-name>
    copyMethod: Direct
----
+
Replace `destination` with the name of your replication destination custom resource.
+
Replace `restic-repo` with the path to your repository where the source is stored.
+
Replace `pvc-name` with the name of the persistent volume claim where you want to restore the data. Use an existing persistent volume claim for this value, rather than provisioning a new one.

The restore process needs to be completed only once. This example restores the most recent backup. For more information about restore options, see link:https://volsync.readthedocs.io/en/latest/usage/restic/index.html#restore-options[Restore options] in the VolSync documentation.
